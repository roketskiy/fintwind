## 目标
让 opencode2 的子代理在父会话内可见、可追踪、可点击，并在右侧栏显示真实的结构化流式对话，而不是目前仅显示工具参数或压扁后的输出文本。

## 现状根因
- `crates/fintwind-core/src/driver/opencode.rs` 的 SSE 读取器只接受父 `sessionID`，其他会话事件被丢弃。
- `crates/fintwind-core/src/driver/native.rs` 在原生会话列表中无条件跳过带 `parentID` 的子会话，因此子会话无法作为工作项被发现。
- `BackgroundWorkKind::Subagent`、任务胶囊和 `RightPanelSurface::BackgroundWork` 已存在，但当前 OpenCode 驱动没有任何 `Subagent` producer，面板只能展示普通 `output` 字符串。
- 前端/桌面已有 `BackgroundWorkEvent` 的传输、归约、点击和停止链路，可以复用，不另造一套“子代理窗口”。

## 实施步骤

### 1. 扩展 provider-neutral 子代理转录协议
涉及：
- `crates/fintwind-protocol/src/model.rs`
- `crates/fintwind-protocol/src/provider_session.rs`
- `crates/fintwind-protocol/src/driver_wire.rs`
- `crates/fintwind-core/src/daemon.rs`

新增一个轻量、可增量应用的 `BackgroundWorkTranscriptEvent`（名称可按现有命名习惯落地），至少覆盖：
- 子代理用户提示/启动消息；
- 文本增量；
- reasoning 增量；
- 工具活动的开始、更新、成功、失败（复用 `ActivityItem` 的结构和 `source_id` 关联）；
- 子代理回合成功/失败结束；
- 必要时的完整 `NativeTranscript` 快照，用于首次点击或驱动重连后的补齐。

在 `BackgroundWorkEvent` 中加入 transcript snapshot/delta 分支，保留现有 `Upsert`、`OutputDelta`、`ReconcileLive` 兼容性。不要把完整 transcript 塞进每一次 `Upsert`，避免流式事件按完整文档复制。

同时为 `BackgroundWorkStatus` 补充语义明确的 `Waiting`（若实际 OpenCode 子代理不产生可展示的等待事件，则实现时可保持协议兼容但仅在有可靠 payload 时使用），并同步 `is_live`、`is_stoppable`、状态图标/文案和 TS 类型。颜色和动画继续复用现有语义状态组件。

### 2. 在 OpenCode2 SSE 中发现、路由和维护子会话
涉及：
- `crates/fintwind-core/src/driver/opencode.rs`
- `crates/fintwind-core/src/driver/native.rs`
- `crates/fintwind-core/src/opencode_session.rs`（仅在需要复用请求/路径辅助时）

在驱动内增加按 native child session id 索引的状态表：
- `BackgroundWorkKey = (Subagent, child_session_id)`；
- `parent_id = parent native session id`；
- `control_id = child session id`；
- 标题、角色、模型、提示等从 `session.created/session.updated` 和子会话首条 user message 的多种已知字段形状中归一化；不依赖单一 beta 版本字段名。

将当前“只允许父 sessionID”的过滤改成三段路由：
1. 父会话事件继续走现有 foreground `DriverEvent` 处理；
2. 已知且 parentID 匹配的 child 事件走新的 `BackgroundWork` producer；
3. 其他会话仍然丢弃，避免多个 Fintwind runtime 互相串流。

处理的 OpenCode2 事件族：
- `session.created/updated/deleted`：创建/更新/回收子代理工作项，并触发状态更新；
- `session.execution.started/succeeded/failed`：Starting/Running/Completed/Failed 状态机；失败保留 provider 错误详情；
- `session.text.delta`、`session.reasoning.delta`：转成子代理 transcript delta；
- `session.tool.input.started/called/success/error/failed`：转成结构化工具活动，按 tool id 合并，不重复创建；
- 能可靠识别的 form/permission 等等待状态：转为 Waiting/detail（不把私有控制标记写入对话）。

保证父会话 `TurnFinished` 不会结算仍在运行的 child；child 的结束事件独立决定其状态。父会话完成后，已创建的子代理条目继续保留，直到 child 自己结束或 reconcile 判定丢失。

### 3. 增加 OpenCode 子代理的刷新和停止控制
涉及：
- `crates/fintwind-core/src/driver/mod.rs`
- `crates/fintwind-core/src/driver/opencode.rs`
- `crates/fintwind-core/src/daemon.rs`（仅复用既有命令转发）

实现 `OpenCodeDriver` 的 `refresh_background_work` 和 `stop_background_work`：
- refresh 在 provider 线程/后台请求中列出当前父会话的 child sessions，作为 `ReconcileLive` 的权威 live 集合；不能在 UI render 中做网络请求；
- 初次发现的 child 以 Starting/Running 进入 registry，已有 child 保留事件驱动的完成状态；
- stop 对 child session 调用 opencode2 的 `/api/session/{child}/interrupt`，使用既有 `StopRequested/StopFailed` 流程；
- reconcile 使用 generation/现有 runtime 顺序，旧刷新结果不能覆盖新事件；对于服务端消失但未结算的 child 标为 Lost，而不是静默删除。

必要时扩展 native session summary 的 `parent_id`，但保留顶层原生会话列表过滤 child 的行为，避免子代理污染主任务侧栏。

### 4. 桌面端保存并渲染真实子代理对话
涉及：
- `src/app/background_work.rs`
- `src/app/streaming.rs`
- `src/app/right_panel.rs`
- `src/app/transcript_view.rs` 或抽取一个可复用的 transcript 子视图模块
- `src/app.rs`

在 `BackgroundWorkRegistry` 中为每个 subagent key 维护独立 transcript projection（消息、turn、活动块、加载状态、generation），而不是继续只追加 `output`：
- transcript delta 按 provider 顺序增量应用；
- 相邻文本/推理 delta 依现有 120ms stream cadence 合并；工具事件按 `source_id` 更新；
- snapshot 只在首次打开/缺失历史时异步获取，带 generation 检查，不能覆盖已经收到的更新事件；
- 对话数据有上限，沿用现有输出/已结算条目上限，避免长期运行的 child 无限增长。

右侧 `BackgroundWork` 面板改成：
- 顶部显示标题、角色、模型、状态、耗时和停止按钮；
- 下方使用与主 transcript 相同的 Markdown、reasoning、tool 活动样式和可滚动/可复制能力；
- child 正在输出时自动跟随尾部，用户手动滚动后不抢位置；
- status 必须同时有图标/文案和颜色，支持键盘 Enter/Space、focus-visible 和 reduce-motion。

保留现有 task capsule 的 Agents 区域和 transcript activity badge，点击都走 `open_background_work_surface`，不新增重复的导航模型。

### 5. Web 客户端同步同一套子代理 transcript projection
涉及：
- `apps/web/src/lib/runtime-context.tsx`
- `apps/web/src/lib/event-reducer.ts`
- `apps/web/src/components/right-panel.tsx`
- `apps/web/src/components/transcript.tsx`
- `apps/web/src/components/fintwind-app.tsx`

同步 TS 协议类型和 reducer：
- 解析新的 snapshot/delta 事件；
- 保持 background item 状态和 transcript 独立归约，事件按已有 `runtimeId/epoch/sequence` 去重；
- `BackgroundWorkPanel` 用真实 transcript 组件/共享渲染路径，而不是 `<pre>` 输出；
- 现有点击、停止、任务胶囊和活动 badge 入口保持行为一致。

### 6. 回归测试和验证
新增/更新测试：
- `crates/fintwind-core/src/driver/opencode.rs`：child created → running → text/reasoning/tool streaming → succeeded/failed；child 事件不泄漏到父 transcript；父 turn 完成不提前结算 child；stop/refresh 路由；多种 `parentID/sessionID` payload 形状。
- `crates/fintwind-core/src/driver/native.rs`：顶层列表仍过滤 child，child 专用发现路径能保留 parent relation。
- `crates/fintwind-protocol/src/driver_wire.rs`：新 background transcript 事件 round-trip。
- `src/app/background_work.rs` / `src/app/tests.rs`：delta 顺序、工具关联、snapshot generation、防止父 turn settlement 误伤 child、状态/丢失处理。
- Web reducer/component tests（若现有测试框架覆盖该目录）：状态与 transcript 增量归约、点击打开、停止和重复事件去重。

验证顺序：
1. 运行 Rust formatter、协议/核心单元测试和 app 测试；
2. 运行 Web 类型检查/测试；
3. 使用现有 dev watcher 等待成功重建；不启动第二个 watcher、不手动重启 Fintwind Debug.app；
4. 按用户给出的真实 opencode2 子代理交互验证：确认 capsule/活动行显示 Starting/Running/Completed/Failed，点击后右侧栏持续显示 child 的文本、reasoning、工具活动和最终结果；确认父 turn 完成后 child 状态仍准确。

不做的事情：不把 child sessions 加入主会话顶层列表、不在 render 中调用 OpenCode API、不用普通终端 `output` 冒充结构化对话、不把 provider 私有控制标记暴露给用户。
