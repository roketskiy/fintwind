# 浏览器协作桥：第二阶段

## 本轮目标

把本地 daemon 中的会话与持有页面的 GUI 连接起来，形成显式共享、读取、
逐次审批操作、撤销 / 人工接管的最小闭环。普通 WebView2 不新增远程调试端口。
上一阶段的 Playwright PoC 和独立测试 profile 保持不变。

本阶段先交付 GUI 与本地 daemon 的安全协作通道，**尚不向 OpenCode 注册
自动浏览器工具**。插件接入属于下一阶段，不能把底层通道的通过等同于
已经完成真实模型调用验收。

## 实现前列出的失败模式

- 未共享页面、错误会话、错误 runtime 或错误 GUI 连接仍能执行。
- 以全局“当前页面”寻址，切换会话 / 标签后操作落到另一页。
- 执行请求进入事件日志，重连时重放点击、输入或导航。
- 审批等待中撤销、导航、关闭页面后，旧请求仍能执行。
- 接管发生在一个多步骤操作中间，后续输入仍继续发送。
- 请求超时、取消或连接中断后自动重试副作用。
- 页面内容、选择器或输入值可以变成任意脚本 / 任意 CDP 方法。
- 密码、隐藏字段、Cookie 或本机文件随快照泄漏。
- 无限快照 / 队列、页面解析或阻塞网络进入 UI 渲染路径。
- 工具插件错误使用插件 location 或进程 cwd 当作当前会话身份。
- 只验证底层 RPC，没有验证真实 WebView2 上的审批与撤销。

## 边界

- 首版只接本地 daemon。授权不持久化、不继承到新连接或新 runtime。
- 共享绑定到具体会话、runtime、页面和随机授权 ID。默认只有观察权限；
  点击、输入、导航必须逐次确认，不提供任意脚本或任意 CDP 工具。
- 请求走定向、即时通道，结果和取消也按请求 ID 匹配；不写入可重放事件流。
- 人工接管 / 撤销立即使旧授权失效。已经发给浏览器的单次动作不能撤回，
  结果不确定时重新观察，不声称取消等于撤销已发生的操作。
- 页面文字与元素信息始终是不可信数据。快照有长度上限，不导出 Cookie、
  密码和隐藏字段，不做“所有网页均兼容”的承诺。
  这不等于自动识别网页中的所有机密：页面自己展示的账号信息、标题或
  可见正文仍属于共享内容。共享前应确认页面适合交给当前会话。
- COM 调用仅在原有 STA/UI 线程异步发起；网络、文件与结果整理走后台。
  CDP 输入的按下 / 释放须依次等原生回调，不依赖请求发送顺序；已发出的
  按下即使随后取消也必须释放，后续输入步骤仍受授权守卫限制。
- 原生适配器首版只支持当前可见页面的主文档、唯一且可见的 CSS 选择器、
  普通文本输入框。不支持跨源 iframe、自动滚动、Playwright 式自动等待或
  任意脚本；第一阶段 Playwright 的更广能力不等于该适配器也已具备。
- Wire 协议升为 8，桌面端与 daemon 必须使用匹配的构建。浏览器请求及结果
  不进入通用重放/响应缓存；连接中断后必须由用户重新共享。
- 取消使用发起方 RPC ID 与 GUI 内部请求 ID 的映射。取消先于请求工作线程
  登记时也会留下有界取消记录，迟到请求不会因此开始执行。

## 验收产物

行为 E2E 保留逐项 JSON 报告、版本和宿主日志。不写单元 / 像素回归测试，
不启动 dev watcher，不使用真实账号，不自动提交或推送。

运行命令（仅 Windows，真实 WebView2、独立测试 profile、本机测试页面）：

```sh
bun run browser:collaboration
```

测试服务使用本仓库真实的 `fintwind-core::server` 和浏览器 broker；只把 provider
后端替换为内存实现，不运行 OpenCode，不读取日常任务数据库。审批通过独立
测试宿主调用与 GUI 按钮相同的方法，不绕过原生授权检查。默认不截图。

## 审查记录

首轮只读审查覆盖生产协议、broker、客户端、页面适配器和 GUI 授权入口。
发现共享发布被拒及 runtime 替换后 UI 仍可能显示“已共享”，已补齐逐 scope
即时回执、按当前 grant 精确撤销以及可读错误提示；这些回执不进入重放流。
另移除 GUI 额外发布工作队列，避免队列满时的旁路破坏消息顺序；发布成功
入队后才更新本地发布集合。GUI 共享数量也在授予前限制为每连接 16 页。
E2E 实现与运行报告不在首轮覆盖范围，完成后另作一次审查，最多两轮。
异常读写退出也通过连接守卫统一清理授权，不能因错误返回遗留孤儿页面。

第二轮只读审查覆盖首轮修复、最终联调和本阶段 E2E，未发现功能性缺陷或
重大漏洞。唯一 P3 发现为断连 / 重连后单次读取 daemon 授权集合可能因清理
线程尚未被调度而误报；已改为有界等待集合清空，再作相同的空集合断言。
两轮审查已结束，不再追加第三轮。

验收边界：E2E 使用独立宿主与产品共用的页面授权 / 审批方法，不覆盖完整
Fintwind 应用的共享按钮、toast 和连接 supervisor 的端到端交互；这些路径
本轮仅编译检查与只读审查。按下后强制释放、取消记录上限满后拒绝执行，
也尚无专门的运行时故障注入验收。真实模型调用仍留在第三阶段。

## 下一阶段：OpenCode 工具

本阶段通过后再把浏览器能力注册到 Fintwind 托管的私有 OpenCode server。
接入时须用每次调用的 `context.sessionID` 映射 Fintwind 会话及当前 runtime，
不能用共享 server 的进程 cwd 或插件 location 当作会话身份；浏览器桥凭据
也不能复用 daemon 主 token。工具取消信号必须传到本阶段的取消通道。
最终验收应覆盖真实 provider 调用与人工接管，而不只验证插件已注册。
