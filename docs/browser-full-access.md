# 内置浏览器完全访问（无授权系统）

> 传输说明：浏览器工具经 OpenCode 2.1.4+ 实验性客户端托管 MCP（`fintwind_browser`，
> 每个工作区一条常驻连接）提供，与定时任务 MCP 同形；OpenCode 内置 `browser_*`
> 由最小屏蔽插件移除。旧版本 OpenCode 缺少该接口时工具不可用，普通对话继续。

## 已确认的行为

- 没有授权系统：没有按页授权、会话绑定、运行实例绑定、打开器权限、逐次审批。页面只按页面标识路由。
- 浏览器工具启用时，所有已打开的浏览器标签都可以被工具使用，手动打开与工具打开的标签没有区别，计划和构建模式也没有区别。
- 工具可以使用密码框、打开本机文件页面；快照可以包含密码、隐藏字段和其他表单值。
- 只有一个全局打开器：新注册会替换旧打开器，所有打开都走当前打开器。
- 页面只随连接生死：连接中断或发布移除时，对应页面下线，未完成的请求按取消处理，不存在跨会话的旧标识复活。
- 浏览器工具的启用开关仍控制工具是否可用；它不是逐页授权。
- 为限制资源占用，每个连接最多同时发布 256 个标签；单次返回内容和元素数量仍有上限。工具支持的操作仍以现有原生适配器为准，例如不等同于任意 CDP 接口。
- 原生页面操作一次只执行一项，避免并行切换标签时操作错页；繁忙时明确拒绝且不发出新动作。

## 实现前列出的失败模式

- 只修改工具说明，实际打开、点击或截图仍等待用户审批。
- 计划模式、模式切换或人工打开的标签仍被错误地排除。
- 后台标签不可操作，或者操作了另一个同名标签。
- 页面加载完成、创建或恢复会话后，已有标签没有被及时发布。
- 导航、同文档 URL 更改或加载失败使页面永久丢失，或旧元素引用指向新文档。
- 连接中断后，旧的页面标识继续生效。
- 操作取消或页面关闭后，等待页面可见的请求仍继续执行；不确定的副作用被自动重试。
- 密码字段仍不可输入，本机文件 URL 在插件、协议、broker 或原生页面层被拒绝，快照仍遗漏用户明确要求开放的字段。
- 浏览器状态显示为需要共享或审批，但实际上没有对应步骤。
- 实验使用日常浏览器 profile、真实账号、真实数据目录，或清理了非本次创建的进程。

## 验证边界

优先验证页面路由、取消、URL 和快照行为。原生 WebView2 验证必须使用独立 profile、独立数据目录、环境白名单和能够证明子进程归属的边界。不能满足这些条件时不运行该验证，不把模拟宿主或编译成功表述为完整 GUI 验收。

本次按用户要求不执行构建检查。旧 `browser:collaboration` runner 尚未证明环境白名单和 Windows 子进程容纳边界，不能直接用于本次验证；新增的端到端检查尚未执行。

## 线上兼容说明

- `BrowserScope` 的 `sessionId`、`runtimeId`、`grantId` 仍保留在线协议上，但全部被忽略，只认 `pageId`。
- 工具线协议的 `sessionId`、`grantId` 同样保留但被忽略。
- `BrowserScopesRevoked` 已删除；`BrowserShareRejected` 只用于发布校验（重复页面、标题超长、坏 URL、超量），不再表示授权决定。
