# Git 历史面板

历史面板参考 Ely 的 CommitGraph（其源码中对应 `CommitList::graph()`），
使用真实父提交绘制分支轨道、分叉和合并节点，没有引入 Ely 运行时依赖。

## 展示与操作

- 提交标题是第一层信息，分支与标签使用紧凑徽标；第二行显示短哈希、作者和时间。
- 左侧彩色轨道表示父提交关系；合并提交用空心节点，HEAD 有额外光环。
  连线结构和节点形状承担含义，不仅依赖颜色。
- 当前历史顶部提交的第一父提交链固定在主轨道，支线在共同祖先节点汇入，
  不因支线先访问共同祖先而让主线换色。颜色代表轨道，不是 Git 分支的固有属性。
- 保留 HEAD / 指定分支筛选，显示所选引用可达的历史，不自动改成所有分支。
- 点击行，或在列表聚焦时按 Enter / Space，复制完整哈希；上下方向键移动选中项，
  Home / End 跳到首尾。刷新按钮也支持 Enter / Space。
- 选中行后，下方显示完整标题、哈希、作者和全部引用。Tab 可聚焦详情区域，
  方向键滚动、Home / End 跳到首尾，Escape 返回列表；完整名称不依赖悬停。
  详情区保留固定高度，首次选择不会缩小列表视口并遮住末尾选中行。
- 每次最多读取 500 条。窗口外的父提交保留向下延伸的轨道，不伪造根节点。

## 数据与性能边界

- `crates/fintwind-core/src/git_log.rs` 在后台读取 `%P` 父提交并使用 `--topo-order`，
  保证子提交先于父提交，即使提交时间存在偏差。不会访问网络或执行 fetch。
- `crates/fintwind-client/src/git_history.rs` 是纯内存轨道布局；历史读取完成后
  在后台计算一次，和提交数据一起缓存。渲染通过共享快照读取，不逐帧遍历历史。
- `src/app/git_history.rs` 保留 GPUI 虚拟列表，每次只绘制可见行的轨道和信息。
  所有行共享轨道跨度；窄面板压缩轨道间距，不裁掉分支。字号变化会同步行高。
- 无变化的刷新在后台比较并复用快照，不重置滚动位置；新提交到达时按原提交
  哈希恢复浏览锚点和选中项。仅字号变化使用保留锚点的重新测量。
- 原有查询 token 继续拒绝刷新或切换筛选前的过期结果。

## 非视觉验证

```sh
cargo run --locked -p fintwind-core --example verify_commit_graph -- <仓库外的输出目录>
```

验证器创建独立 Git fixture，不改动工作仓库，通过 daemon 的 workspace 执行入口、
协议 JSON 往返和客户端轨道算法检查合并关系、时间偏差、引用、未推送状态、
分支筛选、截断、空仓库与错误状态。输出 `commit-graph-report.json` 和 fixture，
可复跑并用 Git 独立核验。它不验证窗口绘制、真实 socket 传输或鼠标/键盘事件。

轨道分配算法改编自 Ely 提交 `e17e31a6890c09ebcfa8b61133d7bc7c625edf69`
的 `src/git/graph.rs`，许可见 [Ely MIT 声明](licenses/ely-gpui-components-MIT.txt)。
