# Issue 6：Git 变更视图优化方案

本文对应 [Issue #6](https://github.com/roketskiy/fintwind/issues/6)。目标是在大型项目中及时显示文件变更，区分 Git 状态，并支持查看嵌套仓库。实施进度和尚未完成的工作如下。

## 实施进度（2026-10-27）

- 已拆分已跟踪、未跟踪和已忽略查询，目录按展开层级请求；已暂存、未暂存、未跟踪和已忽略分别展示。刷新时会按原有展开状态重新加载未跟踪目录，选中文件的查询优先。未跟踪目录全部加载前，不执行针对整个未跟踪组的批量操作。
- 目录列表按直接子项排序分页，每页 512 项，返回下一页游标和截断状态；空页自动续读。已忽略目录的展开只取下一层：直接子项由目录枚举，忽略状态由 `git check-ignore` 判定，已跟踪文件不进入忽略组。输出预算耗尽时标记为不完整，不再让整个请求失败。
- 普通工作区差异按选中文件请求，默认读取少量上下文；分支菜单查询不再顺带计算工作区增删行数。
- 所有 Git 子进程共用同一并发上限：全局 4 个，交互请求优先，后台请求让位。状态、目录、差异、分支、历史、检查点、提交和工作树操作都已接入；排队、执行和输出读取分别受时间与大小预算约束。
- 声明的子模块及已发现的嵌套仓库有独立节点，进入子仓库时切换操作范围。嵌套仓库发现改为工作区级有界扫描，限制目录数、深度、仓库数和耗时，跳过符号链接、重解析点与被忽略目录；发现不完整时显示状态。
- 状态、未跟踪、忽略目录、嵌套仓库发现和单文件 diff 查询支持向其原 daemon 连接发送取消请求，停止查询持有的 Git 子进程。
- 新增有界缓存，只保存不可变结果：单个提交的 numstat 和已结束回合的完整 diff。缓存键包含工作树路径，条目数与字节数都有上限，超过十分钟的条目在下次写入时淘汰，回合引用被删除或恢复时按工作树失效。工作树状态、目录页和单文件 diff 仍未缓存：可靠失效需要文件事件监听，daemon 目前没有 watcher，缓存这些结果会显示用户已经改过的内容。
- 历史差异仍使用原有的整体快照路径，并计入上述缓存。
- 已确认的未跟踪文件仍逐文件删除。展开受限的目录显示“继续加载”或“列表已截断”，但不能直接批量丢弃。
- 本轮补充了 `crates/fintwind-core/examples/git_listing_blackbox.rs`，在隔离临时仓库验证分页、折叠、忽略目录和嵌套仓库发现。未进行性能测量，也未做界面视觉验证；各项性能验收仍需实际测量。

## 已确认的现状

- `git_status::inspect` 执行 `git status --porcelain=v1 -z --branch --untracked-files=all`。它没有请求忽略文件，但会枚举未跟踪目录里的每个文件。
- 源代码控制视图已有暂存和未暂存分组。未跟踪文件目前包含在未暂存组内。
- 普通工作区差异通过临时索引捕获整个工作区，再生成整个范围的完整上下文 patch。32 MiB 限制在 patch 生成后才检查，超限还要重新生成一次简略 patch。
- 状态刷新后会请求分支信息。当前分支查询还会计算工作区增删行数，并读取部分未跟踪文件。
- 状态和差异查询已经在后台运行，结果使用 generation 防止过期覆盖。变更列表已经使用虚拟列表。这些机制应继续保留。

用户报告了忽略文件干扰和加载缓慢，但现有证据不能证明忽略文件是卡顿原因。`.gitignore` 不会让已跟踪文件停止显示。实施前需要收集用户的版本、仓库结构、示例路径及对应的 `git status` 和 `git check-ignore` 结果。

## 产品行为

每个仓库节点拥有四个分组：已暂存、未暂存、未跟踪、已忽略。空分组可隐藏，已忽略组保留可展开入口且初始不查询数量。部分暂存的文件同时出现在已暂存和未暂存组，每行打开对应的差异。

未跟踪目录以目录节点展示。展开后才读取其下一层内容。已忽略组默认折叠；首次展开时才开始查询，忽略目录继续逐层展开。加载中、失败、结果不完整和空结果必须可区分。结果超过预算时显示“继续加载”或明确的截断状态，不得伪装成完整列表。

仓库节点下继续使用目录树。普通目录和 Git subtree 属于父仓库；真正的子模块或嵌套 Git 仓库才有独立仓库节点。子模块节点应区分父仓库记录的提交指针变化与子模块内部文件变化。

所有鼠标操作提供等效键盘操作。沿用现有焦点、主题、翻译和虚拟列表机制。过滤、折叠、切换仓库和刷新不应意外改变提交范围。

## 查询与差异

### 状态查询

进入 Git 视图时优先请求当前仓库的已跟踪状态和分支摘要，独立请求未跟踪目录摘要。已跟踪结果不必等待未跟踪目录扫描完成。刷新时保留上一份可用结果，并标记正在更新。

未跟踪查询先返回目录级结果，展开某目录后只请求该目录下的内容。以 Git 的忽略规则为准，包含仓库、全局和 `.git/info/exclude` 规则。已跟踪文件即使命中忽略规则仍按已跟踪状态显示。

已忽略条目走独立的按需查询。实现时验证 `git status --ignored=matching`、`git ls-files` 等命令在文件忽略、目录忽略、例外规则和目标 Git 版本下的行为。不要假定 Git 原生命令提供稳定分页：若结果无法在预算内完整返回，明确标为不完整，并提供可继续的受控查询或进一步缩小目录范围。

分支名称和分支列表与增删行统计分开获取。只有界面确实需要统计时才在后台计算，避免状态刷新顺带读取大量未跟踪文件。

### 单文件差异

普通 Git 视图先显示状态列表。选择文件后，针对仓库、文件和所选状态计算单文件差异：

| 选择 | 比较对象 |
| --- | --- |
| 已暂存 | HEAD 与 index |
| 未暂存 | index 与工作区 |
| 未跟踪 | 空文件与工作区文件 |
| 已提交或回合审查 | 选定的两个稳定 Git 对象或现有回合快照 |

默认生成有限上下文，按需增加当前文件的上下文。不要在首次查看一个文件时捕获整个工作区，也不要为了得到文件列表生成全仓库 patch。历史回合审查继续使用其既有稳定快照，避免把回合边界变化混入普通 Git 浏览优化。

同一文件的旧路径、新路径以及暂存侧必须随请求传递，正确处理重命名和部分暂存。无 HEAD 的新仓库按空树比较。冲突文件需要独立状态和明确的冲突视图，不能把未合并 index 当作普通文件。二进制、文件删除、模式变化、子模块指针和超大文件需要明确显示状态。

单文件 diff 的 stdout 和 stderr 在读取时就受大小、时间与内存预算约束；超限后返回可识别的降级结果，而不是先收集无限输出再判断。具体预算先作为可调整的内部默认值，实施后根据实测确定。按需展开上下文时，若工作区文件已变化，重新计算当前文件并整体替换结果，避免拼接不同版本的内容。

`-U3` 能减少输出和解析量，但不保证 Git 只读取修改附近的内容。`--numstat` 也可能需要计算内容差异，不能把它视为免费操作。

## 缓存和刷新调度

状态、目录和单文件差异各自缓存。缓存键至少包含执行位置、仓库工作树身份、文件路径、比较类型及影响结果的选项。工作树身份不能只用 Git common directory，因为多个 worktree 可能共用它。远程路径在 daemon 所在主机解释，不能由桌面客户端按本机路径规范化。

不可变 Git 对象的结果可按对象 ID 复用。工作区和 index 的缓存依赖明确的失效信号：本应用的 Git 写操作、文件事件、分支切换、手动刷新和重新连接都应使相关结果失效。文件事件合并后刷新；事件丢失、监听溢出或不可用时，以完整刷新恢复正确状态。generation 继续阻止过期结果覆盖新结果。

每个仓库的同类刷新应合并为有限数量的在途工作。选中的文件优先于后台统计和未展开节点。取消请求需要传达到 daemon 持有的任务及其本轮创建的 Git 子进程；仅让客户端超时或丢弃结果，并不会停止 daemon 中的工作。不得按进程名、路径或端口扫描并终止其他进程。

缓存必须有条目数和字节上限，并在仓库关闭、连接断开或长期不用时释放。部分结果、过期结果和完整结果使用不同状态，不能参与全量操作。

Git 的 untracked cache 和 FSMonitor 可作为可选的后续优化。先测量收益和兼容性，不自动修改用户的 Git 配置，也不假定所有工作区都支持它们。

## 仓库发现与操作边界

先识别当前仓库和 Git 声明的子模块，再在工作区范围内后台发现嵌套仓库。识别 `.git` 目录和 `.git` 文件，支持 linked worktree。扫描要可取消、有并发与数量预算，并跳过符号链接或重解析点形成的循环。被忽略的目录默认不做深度发现；用户主动展开或明确添加路径时再检查。发现尚未完成、预算耗尽、无权限和未初始化子模块都需要可见状态。

独立仓库节点的状态、diff、暂存、撤销和提交均使用该仓库的工作树路径及仓库内相对路径。父仓库的“全部暂存”和提交不递归操作子仓库内部文件。子模块内部提交与父仓库暂存子模块指针是两次独立操作。

文件操作应使用字面路径和结构化参数，正确处理空格、Unicode、换行、前导 `-` 和路径特殊字符。daemon 验证路径属于目标工作树，并处理符号链接及路径逃逸。忽略文件默认不提供批量强制添加或批量删除。任何涉及未跟踪文件删除的撤销操作继续要求明确确认。

## 实施顺序

1. **建立基线。** 在独立仓库记录状态、分支统计和 diff 的各自耗时、输出字节、峰值内存和 Git 进程数。覆盖首次与重复访问。复现条件不足时保留该不确定性。
2. **减小普通 diff 范围。** 状态列表先显示，选中文件后加载有限上下文；保留历史回合审查。拆出分支行数统计。
3. **实现分类和按需目录查询。** 独立显示未跟踪和已忽略；验证忽略规则、部分暂存及截断状态。
4. **加入刷新调度与有界缓存。** 合并请求，传播取消，处理监听失效和快速切换，控制后台并发。
5. **实现嵌套仓库。** 先支持已声明子模块，再支持有界发现的独立仓库，并明确所有写操作范围。
6. **完成整体验证。** 在隔离仓库和真实应用路径下验证交互、正确性及性能，与第一步同一数据集比较。

各阶段完成后都应可独立验证。不要先引入新的 Git 库或自行重写 diff 算法；只有测量确认现有 Git 命令或算法是主要瓶颈时，才比较替代实现。

## 验收

使用本轮创建的独立数据目录和受控进程进行整体黑盒或端到端验证，不新增单元测试。测试结束只清理本轮创建并持有句柄的进程和数据。

- 同一文件部分暂存时，两组显示正确，暂存、撤销暂存和工作区撤销作用于正确的一侧。
- 新仓库、重命名、删除、二进制、冲突、特殊字符路径和工作区文件在加载中变化的情况有明确结果。
- 未跟踪和已忽略目录逐层加载；忽略规则、例外和已跟踪文件的语义与 Git 一致。关闭忽略分组时不枚举其内部文件。
- 子模块未初始化、内部修改、父仓库指针变化、嵌套仓库和 linked worktree 均显示正确；批量操作不跨仓库。
- 快速切换文件和仓库、重复刷新、daemon 断连、查询超时和取消时，不显示过期内容，不留下无主 Git 进程。
- 大量文件和超大单文件下，列表与单文件 diff 分别测量。记录首屏、选中文件到可阅读、刷新耗时、输出字节、峰值内存和并发进程数。冷缓存和热缓存分开报告，注明机器、Git 版本与仓库规模。
- 达到预算的结果明确标为不完整，用户仍可通过缩小范围或继续加载访问其余内容。任何批量写操作必须针对完整且明确的选择。

验收数值应根据基线与目标机器确定。未经实测，不承诺具体加速倍数或延迟。
