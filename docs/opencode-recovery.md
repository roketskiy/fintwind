# OpenCode 私有服务的事件恢复

## 边界

Fintwind 继续使用自己的 `opencode serve`、原有共享会话数据库和 daemon
生命周期。不修改 OpenCode，不停止公共服务，不更改其配置或服务注册。
模型发现必须使用同一个私有服务，不能调用会自动发现/启动公共服务的 CLI。

仅修改客户端不能提供跨 OpenCode 进程的执行锁；外部服务同时操作同一会话的
风险仍然存在。这里解决 Fintwind 自己的隐式服务启动和错过通知后无法收敛。

## 实现前定义的失败场景

以下是行为验收，不检查源码字符串是否变化：

1. 模型发现启动公共服务，或与会话使用不同私有服务。
2. 工作区目录未传递，模型档位或成功空目录语义丢失。
3. SSE 行被 TCP 分片、HTTP chunk 边界、200ms 读取超时或 UTF-8 边界拆开。
4. 非 200/非 SSE 响应被误认为已建立订阅。
5. SSE 断开，但服务还活着：不能把连接故障误报为进程退出。
6. 心跳仍在，但回合结束事件丢失：必须用原生数据主动对账。
7. 最后一条 assistant 已结束，但它只是工具调用的模型步骤：不能结算回合。
8. 消息列表只含上一轮回复，或当前输入仍在 inbox：不能结算当前回合。
9. 对账期间到达新事件或新提交：旧结果不能覆盖较新的状态。
10. 断线期间文本、推理、工具结果缺失：结束前补齐，已收到的 part 不重复。
11. 正常长推理/长工具期间没有业务输出：不能超时失败或自动重发 prompt。
12. 实际私有进程退出或 daemon 关闭：停止订阅和后台工作，保留原有退出语义。
13. 仅发送 PDF、文本文件或目录附件，文字为空：原生 user 仍是合法输入，
    不能因为图片导入器没有生成附件而丢掉该行、永久拒绝正常终态。
14. 模板命令展开后的 provider 文字与本地 `/name …` 不同：以实际发送文字
    绑定初始输入，恢复后保留用户原始文字和附件；不能静默丢弃 snapshot
    后把不完整的本地回答标记为成功。

## 同步方式

- 每个端口仍只有一个共享 SSE 读取器；传输错误自动退避重订阅。
- 连接活性由收到的原始数据（含心跳）判断，不由模型输出判断。
- 读取器仅解码并广播，慢查询在独立后台工作中执行。
- 驱动在重连或活跃回合长时间无事件时查询原生状态与本轮消息。
- 原生 `idle` 消息的 outcome / 会话 `time.idle` + outcome 是结束事实；
  一条 assistant 的 `time.completed` 仅表示步骤结束，不足以结算回合。
- 使用提交返回的原生输入 ID、提交时间和本地提交代次限定本轮；
  检查对账期间实时事件和连接代次没有变化后才应用结果。
- 提交前为 V2 prompt 指定原生输入 ID。响应丢失时保留这个标识，
  查询原生记录而非盲目重发；明确的 4xx 拒绝仍按原有失败路径结算。
- 重新连接后收到的终态不能证明之前的内容完整：先补齐该回合的持久化内容，
  再发布本地结束事件。旧连接的结果不能结算新提交。
- 回合结束事件也须验证最新输入已经离开 inbox 并出现在持久化消息中；
  HTTP 接收响应本身不能解除此屏障。
- 成功应用恢复窗口后，保存原生 idle 时间与消息 ID；迟到的旧文本／工具／
  执行事件依据原生信封过滤，不能泄漏到下一次输入。同毫秒用原生可排序 ID
  判定，缺少可证明的信封时不猜测；不按客户端接收时间过滤新执行。
- 后台按原生顺序翻译完整本轮窗口，通过单个 `turnTranscriptReconciled`
  事件原子替换本轮投影，再发布结束事件。不零散追加丢失 part，避免把早期
  内容排到重连后已显示的较晚内容之后。保留历史、用户显示文字与附件。
- 服务主动续跑用原生执行事件的时间和可排序事件 ID 定位前一个 idle 分隔符；
  只有读到完整窗口才恢复，只替换本次续跑的后缀，不删除之前已完成的回复。
- 首次 SSE 握手尚未成功也允许已提交回合在静默后对账；查询不依赖订阅活跃。
- 对账失败保留“未知”，不能默认成功。所有查询有超时、分页和内存边界。
- 空文字的附件输入在恢复翻译中仍须保留 user 行，不能依赖图片导入器的结果。
  本地附件的显示与句柄仍由客户端的原始输入提供，不生成虚假的占位文字。
- 模板展开时将真正发出的初始文字绑定到本地回合元数据，恢复据此识别输入，
  显示仍保留用户键入的命令。复用已有回合 JSON 存储，不修改共享 OpenCode
  数据库，也不新增 Fintwind 数据库列。
- 若本地投影拒绝完整窗口，必须明确报告本地同步失败，不能继续展示成功结束
  或自动发送下一条排队输入。

默认 15 秒没有本会话事件时触发对账，重连会提前触发；一次只有一个后台
查询在途。读取本轮而非整个历史，消息窗口最多 25 页、每页 200 条，
累计 JSON 内容最多 16 MiB，分页有 12 秒预算，每个 HTTP 请求超时 3 秒。
超过边界保持未知，不用不完整历史判定成功。

## 脱敏诊断

后台同步记录写入 Fintwind `app.db` 同目录的 `opencode-sync.log`。开发版
位于仓库的 `temp/`，正式版位于 Fintwind 本地数据目录。只记录时间、端口、
本地代次和固定原因代码，不写提示词、消息、工具输出或鉴权信息。
日志达到 2 MiB 后停止追加（stderr 仍保留诊断），不无限占用磁盘。

## 验证

协议依据：OpenCode `v2.0.16` 与 `v2.0.19` 的
`packages/schema/src/session.ts`、`packages/schema/src/session-message.ts`、
`packages/schema/src/session-inbox.ts` 和 `packages/protocol/src/groups/session.ts`。
已核对输入 ID、inbox 接收响应、持久化 idle/outcome、进程内 active 查询的语义；
active 列表缺席不能证明其他进程也已停止。

使用本地假 OpenCode HTTP/SSE 服务，通过真实 Fintwind daemon、WebSocket 客户端
和驱动验证。保留请求计数、事件时序和 JSON 验收产物；不连接真实供应商，
不碰用户 OpenCode 数据库。真实 provider 验证须与模拟端到端结果明确区分。

Windows 本地验收（需要 PATH 中可用的 Python）：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/opencode-recovery-e2e.ps1 -Long
```

默认执行快速矩阵；`-Long` 再用单独测试进程验证 15 秒静默触发与忙碌／旧回合
否决、服务主动续跑、附件输入与模板命令。不能把这些矩阵放入同一个测试
进程：daemon 退出会永久关闭该进程的私有服务池，这是现有生产生命周期的
保护，不应为测试绕过。
产物位于 `temp/recovery-e2e/<uuid>/`：`result.json`、`result-long.json`、
`result-r2.json`、`result-p1.json`、`result-p2.json`。每次生成唯一目录，
不清理用户既有文件。场景细目以产物记录为准，不把模拟验收当作
真实供应商或桌面视觉验证。

验收重点：

- 快速矩阵：唯一私有服务／鉴权／工作区模型隔离；真实 chunked、UTF-8、
  CRLF 与半行暂停；断流后仅收到终态仍先补齐；长工具／旧回合否决；
  steer 已接收但仍在 inbox 时不能被旧终态结算；第二次输入后收到的旧回合
  文本不能被派发。分片场景在流式发送期间保持 active，不能让预置的 idle
  使 HTTP 补齐抢先结算、掩盖流解码结果。
- 长矩阵：有心跳但无终态；首次 SSE 永久拒绝仍能 HTTP 对账；长工具／
  上一轮 idle 的静默否决；真实本地时间下丢失提交响应不重发、不误报失败。
- 主动续跑：原生执行信封定位之前的 idle、丢失内容后重连补齐、只替换续跑
  后缀并保留已经完成的回答。此验收等待两次结算，不能在第一轮完成后退出。
- 投影契约：原生文本／工具／推理顺序、幂等替换、用户反序确认时附件不交换、
  不完整窗口不丢本地输入。没有新增生产用测试开关。
- 附件输入：实际 POST 空文字、PDF／文本文件／目录三个附件；实际恢复事件
  的 user 文字必须为空，客户端按该事件恢复后仍保留三个本地附件。
- 模板命令：用真实 `expanded_submission` 展开，经真实 daemon 链路断流恢复；
  初始发送绑定通过回合 JSON 往返保留，最终仍显示原始 `/deploy staging`
  和本地附件，而不是展开的 provider 提示词。

复审后补充的失败证据：

- `temp/recovery-e2e/cac55df2b1a4440daacc8d71c1c4ef38/result-p1.json`：空文字附件
  输入未被翻译，正常终态未结算。之前的假服务以 `if text` 检查忽略空字符串，
  使该场景残留默认 `prompt` 并产生假通过；现在保留真实空字符串并检查实际事件。
- `temp/recovery-e2e/9adfaaefb48b4e8b91760234e220c396/result-p2.json`：展开文字与
  本地命令不匹配，投影替换返回 false。补充了实际发送文字绑定与原始输入保留。

这两项经第二次代码审查发现，修复后重跑验收，不额外启动第三轮审查。

补充旧内容围栏的失败证据：
`temp/recovery-e2e/9cd29b1c9625463bb2bf30d01e616d1c/result.json` 中的
`6_previous_turn_does_not_settle_new` 记录第二次提交后旧 delta 仍被派发；
已加入原生完成边界过滤。该产物中的分片场景已通过。

仍需区分的验证边界：未调用真实供应商；未做桌面视觉验收；真实 OpenCode
进程崩溃的 `ProcessExited` 正例未由此模拟矩阵覆盖。正常 daemon 退出会清理
模拟私有服务，但这不等同于真实进程故障验收。旧版桌面端不认识新恢复事件，
因此更新时桌面端与 daemon 必须来自同一构建，不应只替换其中一个。
