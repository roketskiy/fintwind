# 界面性能约定

正式桌面应用使用 MyGo。正常交互以至少 60 FPS 为目标，流式输出还需兼顾更新延迟
与 CPU 开销。旧 Rust/GPUI 的帧循环、pulse clock 和测量结果不适用于 Go 版。

## 界面与后台边界

`cmd/app` 的 view、行构建器和测量只读取内存。文件遍历、Git、网络、数据库及子进程
操作交给后台任务，结果通过 `Window.Update` 发布到界面状态。
切换会话、数据源或关闭窗口后，取消旧任务并拒绝过期结果。

`ui.Context` 和 `ui.Element` 只在当前构建期间使用，不能存入应用状态或交给 goroutine。
持久的控件引用使用 `ui.Handle`。MyGo 的约束以根 `go.mod` 固定版本为准。

## 长列表与流式输出

长集合使用 `ui.List` 虚拟化，行使用稳定身份。集合级筛选、排序和派生状态应缓存，
不能在每个可见行中重新遍历整个会话。后台事件合并后再发布，避免每个 token
触发全量重建，也不能通过无限动画维持刷新。

## 验证

性能改动应覆盖长文本、多会话、流式输出和滚动场景，分别观察空闲与活跃状态的
CPU、分配量、后台任务数量和界面响应。测量时记录构建版本、数据规模与操作方式，
确认后台工作已完成，避免把缓存命中或空操作当作性能提升。

构建与生命周期静态检查见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
行为验证工具位于 [tools/e2e](../tools/e2e)，使用独立数据与受控进程。
