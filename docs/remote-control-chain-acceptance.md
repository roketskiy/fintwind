relay、host 和 daemon；模型服务可以使用仅监听 loopback 的合成 provider。
不得把 mock UI、直接写 relay 配对表或单函数调用计作本清单通过。

## 失败方式与判据

双 host 实现前失败清单：第二次配对不得覆盖第一台的可信记录；hostId 相同
但公钥/relay 不同不得隐式替换；失败配对不得丢失原授权。切换目标先关闭
旧通道并清除会话、项目、offers、队列视图、批量选择和未提交输入，不把旧
异步事件送入新视图；不重发任何副作用。设备身份复用，授权仍逐 host。
同一 relay 一次仅连接当前 host；选择另一台不自动给它配对。忘记当前电脑
仅移除该记录，撤销一台的 grant 不影响另一台。旧单 host 记录只迁移可信
元数据，不读取或迁移业务正文；存储损坏拒绝静默生成身份。

daemon 单独崩溃恢复补充失败清单：仍存活的 host 不得把其已持有的 operationId
再次 enqueue。否则原 queued 项变为两个可见条目，取消一个后另一个仍可
派发。恢复按原 ID 原位对账而非重复加入，以 daemon 持久 state 为准，保留
已接受的 cancel binding；断链窗口的本机终态猜测不应吞掉实际仍 queued 的条目；
取消后不得有同 ID 的 queued/dispatching 副本，不重复发送 provider prompt。

手机取消精确 C 查询验收补充：从隔离 host 的只读 operations 库读取手机
产生的 cancel_target/C，不自造成功取消记录；用其真实 grant/host/device
查询 daemon。错误 C、target、host、device、grant 必须 unknown，重复正确
查询保持同一 cancelled 绑定；查询前后 ListRemotePrompts 字节一致，不
写库、不重新 Cancel/Dispatch。缺失合成目录标记或非 cancelled 结果失败。

手机恶意 wire 验收编码前清单：独立页面使用实际 vault 与发布 WASM，关闭
正常 UI 通道后建立新 KK，通过真实 relay/host 发合法加密 ReadFile/Directory。
路径穿越、绝对路径、凭据文件、自报 cwd、另一项目须拒绝且不返回正文。
接收正文仅内存检查，产物只记录 case/状态；不导出或打印身份，不在发布
bundle 注入测试接口，不发送任何写操作。前后核对工作区字节与 grant。

## 只读边界独立黑盒

`../fintwind-pwa/scripts/workspace-reads-blackbox.mjs` 启动实际编译的
`workspace_read_probe` 外进程，操作唯一合成目录与真实 Git 仓库。验证文件与
目录分页、凭据过滤、符号链接、UTF-8/大小、revision、Git 对象/refs/index 不
被读取操作修改、textconv/fsmonitor 不执行、HEAD/index/工作树正文来源隔离。

这只证明完整读取模块的边界，不证明手机授权、密文传输或 daemon 适配；这些
仍由上面的真实链路矩阵覆盖。平台不允许创建链接时保存 skipped，并且不把
该情景计作已通过。

只读差异还须验证真实规模的普通项目：至少 500 个不同的未修改文本文件，
同时含未修改二进制资源和少量文本修改。不能逐文件启动 Git 导致 10 秒截止
被正常项目耗尽，也不能因无关未修改二进制资源拒绝全部文本差异。所有 Git
对象与工作树扫描设整请求字节预算；超预算明确拒绝，不无界读取。
Partial-clone 缺失对象只能返回不可读，不能触发 lazy fetch、remote helper 或凭据
helper；手机查看差异不是访问 Git 远端或执行仓库配置命令的授权。
硬链接没有可规范化的唯一目标路径，普通名称可能指向项目外或已知凭据文件。
因此同一打开文件有多个硬链接时拒绝正文读取；用合成文件验证外部和凭据别名。
已跟踪文件所在的多层目录全部删除时，仍须显示文件删除差异；不能因为直接
父目录已不存在，就把真实删除静默当成没有变化。只沿项目内的可信祖先核验。

只读 diff 不能直接调用本机 `CollectReviewDiff`：现有实现会生成 checkpoint
Git 对象。远控适配使用纯 Git 对象读取与经句柄核验的工作树文本快照，返回
有界文本差异；不执行外部 diff、textconv、clean filter 或 fsmonitor，不把工作区写操作藏在
“查看差异”里。正文超过上限时拒绝，不默默截断。

## 页面发布门禁

打包前必须拒绝：缺失安装清单或 worker CSP、blackbox 注入入口进入正式 bundle、
临时 WASM staging 被复制到 dist、glue/WASM 哈希不符、构建期间源码变化，以及
打包后的资产变化。门禁只核验实际发布字节，不把静态扫描当作真实链路验收。
WASM 输入哈希必须包含实际依赖的 `fintwind-protocol`，不能只核对三个 remote
crate，而漏掉密封载荷引用的底座 wire 类型。
发布产物带全资产 SHA-256 和单独门禁结果，后续公网部署复用同一份产物，不重新
构建未验收的页面。
ZIP 要逐项与冻结目录核对字节和 SHA-256，不能因打包工具忽略隐藏文件而让发布
目录与备用上传包包含不同资产。
若页面已由真实链路验证，打包应复用该目录，而不是重新构建。验收报告的
siteSha256 必须逐项匹配，包括资产数目；失败报告、未清理进程的报告、不同
构建的报告不能附为通过证据。局部链路报告不因此升级为 fullPlanVerified。
发布的 WASM 二进制必须导出配对校验码、双方指纹、连接及密封/解封所需接口；
不能只凭协议版本和非空文件接受旧桥。
源记录还须包含当前输入目录的完整文件清单，新增依赖文件不能逃过旧记录核对。
Pages 发布门禁只接受正式 relay 的 CSP；允许 loopback 的私有链路候选不能直接
作为上传包。复用验收时，撤销清理必须明确为 true，null 或缺失不是完成证据。

跨端类型生成须拒绝生成期间的 Rust 输入变化；全部类型准备完毕才替换生成
目录。并发生成、编译/格式化失败不能留下新旧混合的类型；生成目录出现非生成
文件时拒绝替换，不为维护契约而删除用户文件。

### 身份并发与故障补充（2026-10-09）

- 两进程首次生成与旧身份迁移不得读到半对密钥。所有加载和迁移应使用同一个
  操作系统文件锁；进程退出由系统释放，不能按文件时间抢走仍存活进程的锁。
- 留下空锁文件不表示仍占锁；旧空锁文件可再次使用，不删除锁文件制造两个锁对象。
- 密封记录存在但读取或解密失败时拒绝，不能选择旁边的明文。新身份密封失败
  不写明文、不注册、不配对。只保留既有旧明文迁移失败的兼容路径。
- 验证必须使用本轮构建的冻结二进制、隔离环境、进程总截止与清理。不能继承
  模型凭据，不能将原始 stderr 写入证据。输入和二进制哈希在结束时再次核对。
