# 远程控制：自建中继架构设计

## 目标与范围

让 Fintwind 用户能在一台常驻桌面机上跑 agent，然后用手机（或另一台桌面）
管理与控制会话、回答审批、转发指令，并查看只读工作区。本文规定**产品能力范围、
网络架构与协议语义**，不进入实现。

四条铁律，先划清楚：

1. **host 与控制端只建立出站公网连接；relay 接受公网连接。** host 不开公网
   端口，不向控制端直接暴露 IP；relay 仍能看到连接来源 IP，不能承诺 IP 隐匿。
2. **relay 只转端到端加密的应用消息，不做 TCP 隧道。** 消息限于明确列出的
   指令、审批、diff、终端输出、按需截图和通知。不得透明代理任意本地 API、
   daemon 命令或 URL。TLS 保护到 relay 的链路，不能代替端到端加密。
3. **host 是唯一业务状态与执行授权源。** 模型凭据、MCP 配置和权限判定留在
   本机。控制端不运行 agent，但具有实际的远程控制能力，必须按高权限客户端保护。
4. **连接身份固定，消息目标受限，执行前仍须校验授权。** relay 的账号认证与
   路由不能替代 host 对已配对设备、操作范围、审批状态及撤销状态的独立检查。

本文中的“relay 看不到内容”，仅在**可信 host、可信控制端代码、经过认证的
端到端加密及独立本机配对**同时成立时适用。没有这些条件，只能称为“信任 relay
的 TLS 远控”。第一阶段不提供自动回退到业务明文的模式。

### 这一版不做

不做组织与团队、不做同一台 host 的能力分层与协作、不做配额计费、不做高可用多
relay、不做原生手机 App、不做任意端口转发。远端也不开放全局设置、项目新增、
直接文件编辑、Git 写操作、交互式终端、provider/MCP 配置及设备授权管理。

> 可以后置组织、计费和产品配额，不能后置**跨账号隔离、连接与缓冲上限、限速、
> 登录防爆破**。多个账号共用 relay，不只是归属校验，还共享服务器资源与故障域。

## 形态假设

本文按**形态 3** 设计：多个用户各自在自己电脑上装 Fintwind，每人只遥控自己的
host，共用同一套 relay。

三种形态的技术要求差别很大，先对照，避免误用本文结论：

| 形态 | 场景 | relay 是否需要账号 | 是否需要能力分层 |
| --- | --- | --- | --- |
| 1 | 单人自用 | 可不用账号；仍需设备配对与 host 授权 | 不需要 |
| 2 | 多人共享同一台 host | 需要 | **需要**（observe / drive / approve） |
| **3** | **各自 host，共用 relay** | **需要** | 不需要（每人只碰自己的机器） |

形态 2 才会引入能力分层，本文不涉及。但它有一个前提结论对三种形态都成立，见
"威胁模型"。

**形态 3 的一个必然后果**：同一个账号名下可能有多台 host（笔记本 + 台式机）。
控制端应能同时看到它们，但任何操作必须**显式指定 host_id**，不得默认连到"最近
活跃的那台"——那是寻址歧义，也是误操作的常见来源。

## 远程端能力（已确认）

**完整会话功能 + 只读工作区；范围内复用本机功能与业务逻辑，不另造一套远程
停止、继续或回退规则。** 手机适配布局与交互，不改变操作含义。网络授权、去重、
过期检查和状态冲突处理由 host 适配层承担，不作为要求用户重新设计本机行为的理由。

### 第一阶段能力清单

| 类别 | 开放能力 | 范围与行为 |
| --- | --- | --- |
| 会话发现 | 列表、搜索、状态、历史记录、项目筛选 | 已配对 host 的全部会话，包含归档历史；正文按需加载，不一次同步全部内容 |
| 会话创建 | 在已有项目创建会话 | 项目及工作目录由 host 的既有记录决定；不能新增项目、浏览任意磁盘目录或自报 cwd |
| 会话整理 | 重命名、归档及本机已有的恢复归档操作 | 复用本机逻辑；操作不隐式切换其他会话的目标 |
| 删除与批量 | 永久删除；批量归档、停止与删除 | 分级确认、预览明确对象；运行中的会话先停止再删除；逐项报告结果，不删除项目文件 |
| 任务控制 | 发指令、停止、停止后继续 | 停止与继续调用本机既有执行路径；普通发送排队，只有用户明确选择才中断当前任务 |
| 用户问题 | 单选、多选、自定义答案及多题回复 | 复用本机问题流程，绑定有效请求；问题答案不充当执行审批 |
| 工具审批 | 此次允许、拒绝 | 只响应本机仍有效的请求，不创建“以后免审批”规则，不改变本机权限模式 |
| 历史操作 | 分支、回退及对应本机已有操作 | 与本机功能一致；回退可能改变文件，分支不代表自动得到独立工作树 |
| 会话选项 | 已配置模型与 agent 的选择 | 可用项由 host 提供，沿用本机生效时机；不能借选项修改权限策略、配置或凭据 |
| 只读工作区 | 查看已有项目文件、diff、任务输出，复制显示内容 | 复用本机读取路径并受大小与路径范围限制；不提供直接文件写入、Git 写操作或 shell 输入 |

这里的“完整会话”是上述明确范围内的完整管理与控制，不等于把桌面所有功能或
`Command` / `WorkspaceOperation` 整组放给远端。截图仍受已有按需捕获边界约束，
不因开放只读工作区就扩大为全桌面截图或录屏。

### 配对授权范围

- 本机配对弹窗明确说明：**该设备可读取和管理这台 host 的全部会话及其历史，
  包括之后创建的会话，并查看本机已有项目中的文件、diff 与任务输出。** 不再要求
  用户逐会话开放；范围是该 host，不扩展到同账号另一台或未来新增 host。
- 新会话只能在 host 本机已登记的项目中创建；新增项目仍由本机完成。手机选择
  项目 ID，host 决定 cwd、runtime、provider cursor 等内部值，不信任远端原样结构。
- 全部会话可发现不等于全文常驻手机：列表、搜索和读取都经授权，正文与输出按需
  分页、订阅；relay 只见密文，手机端保持不持久保存业务内容的规则。
- 文件读取限制在本机已登记项目内，host 校验实际路径与链接目标；不能用绝对路径、
  路径穿越或链接绕到项目外。“文件可读”也不授权读取专用凭据/配置管理接口。

### 复用行为与明确例外

相对直接复刻本机行为，用户明确指定的规则是：**普通发送排队、显式中断；删除分级确认、先停再删；
本机与远端并用，冲突拒绝。** 其余操作在已开放范围内与本机保持一致。

- 运行中普通发送进入 host 管理的有界会话队列，可查看、取消；不静默改为 steer。
  “停止后发送”显式走本机取消与提交路径。host 已接受队列与手机断线 pending
  是不同状态，不以 relay ack 冒充 host 接受。
- 停止不新增“远端暂停”语义，继续复用本机下一次发送或恢复路径。取消请求已接收
  与实际停止分开报告；仍存在后台工作时如实显示，不承诺回滚外部副作用。
- 回退复用本机历史与工作树处理及已有风险提示，不另加远程专属回退方案；目标会话
  或工作树在确认后变化时按冲突拒绝处理，不静默覆盖另一端刚完成的操作。
- 永久删除必须展示对象与数量并二次确认；运行中的会话先明确停止，host 确认可删除
  后执行。批量动作使用明确对象清单，不重新扩大为确认之后出现的会话；部分失败
  逐项显示，不能把所有对象当成成功。删除使相关输入、审批与订阅失效。
- 本机与手机不抢独占控制权。host 对会话/工作树变更统一做版本检查与原子处理，
  状态过期时拒绝并刷新；这不能只靠 PWA 的按钮禁用实现。
- agent 的工具继续遵守本机已配置权限与执行规则，不强制给原本允许的动作再加一层
  手机审批。远端只回应实际待批请求，不切换 Full Access、不使用 always 创建规则。

**“只读工作区”限制的是直接操作侧栏，不是 agent 的执行能力。** 用户仍可通过
会话指令让 agent 写文件、执行命令或操作 Git；是否执行由 host 既有工具权限决定。
分支与回退也是允许的会话操作，即使它们按本机行为影响文件，也不能由“侧栏只读”
推导出整个远控是只读。它既不是只读账号，也不是文件沙箱。

### 不开放的操作

新增项目、任意工作目录、全局设置、provider/MCP 配置与密钥管理、权限策略变更、
控制设备配对/授权/撤销管理，以及直接文件编辑、Git 提交/推送/切分支和交互式终端
输入均不进入第一阶段远控接口。手机初次配对仍可提交自身配对请求，但不能批准
其他设备、签发 grant 或扩大自己的权限；设备管理在 host 本机完成。

## 为什么是 Codex 路线

调研了 Claude Code Remote Control、Codex Remote Control、ZCode Web Remote
Control、OpenCode serve、Zed、Cursor Cloud Agents。拓扑只有两种，其余差异都在
工程细节：

| 方案 | 拓扑 | 对本项目的可用性 |
| --- | --- | --- |
| Claude Code Remote Control | host 出站 HTTPS 轮询 + Anthropic 中继，SSE 下行 | 不可用：硬性绑 `api.anthropic.com` |
| **Codex Remote Control** | **host 出站 WSS + OpenAI 自有 relay，带序号确认** | **采用其出站中继与投递拓扑** |
| ZCode Web Remote Control | 桌面无监听，作为出站 ws 客户端连 Z.ai relay | 同构；桌面即唯一运行时，值得借 |
| OpenCode serve | 本地 HTTP/SSE，relay 交给第三方隧道 | 已是本项目底座 |
| Zed | SSH 远程执行（collab 是另一套） | GPUI 先例，可参考 |
| Cursor Cloud Agents | 云端 microVM 远程执行 | 反面参照：凭据与 repo 进云 |

Codex 胜出的具体原因：投递层有显式序号与游标补发、中继白名单固定、host 侧有界
缓冲、协议版本显式协商。这四点恰好是 Claude 第一版暴露的真实缺陷（无序号导致
重连后状态静默漂移、单向心跳、URL 即凭据、session 边界泄漏）。

一个额外的产品理由：Claude 与 Codex 的官方方案都要求直连自家模型端点，设了
`ANTHROPIC_BASE_URL` 或走 Bedrock/Vertex 功能直接不可用。自建 relay 没有这个
约束，**必须保持 opencode 的多 provider 特性**，这是相对官方方案的差异化。

以上为调研时的产品与实现快照，不作为本方案已满足安全要求的证明。端到端加密、
设备信任和撤销机制按本文独立设计，不从类似拓扑推导安全结论。

## 架构

```
 手机 PWA            另一台桌面 B          运维 CLI
 (纯控制面)            (可选控制端)
     │                     │                  │
     │  WSS 出站            │                  │
     └─────────────────────┼──────────────────┘
                           ▼
             ┌───────────────────────────┐
              │        RELAY (公网)        │  ← 你的服务器
              │  身份元数据 · 配对协调      │
              │  密文路由 · 有界缓存        │
              │  无业务明文 / 无端点私钥    │
             └─────────────┬─────────────┘
                           │  WSS 出站
             ┌─────────────┴─────────────┐
              │   HOST 守护进程 (本机)      │  ← 独立小进程，不进 GPUI
              │  出站长连 · 端到端加解密    │
              │  设备信任 · 授权 · 去重      │
             └─────────────┬─────────────┘
                           │  localhost HTTP + SSE
             ┌─────────────┴─────────────┐
             │      opencode serve       │  ← 已有，不改协议
             └───────────────────────────┘
```

host ↔ 控制端的业务载荷在进入 WSS 前加密，只在两端解密。relay 与反向代理仅
接触密文、认证材料和必要路由元数据。图中 CLI 若仅做 relay 运维，不持有业务
解密密钥；若作为控制端，必须按普通设备配对，不能凭管理员身份获得 host 控制权。

## 身份与归属模型

实体标识使用至少 128 位不可预测随机值，凭据另行生成。**随机标识降低枚举便利性，
不是授权，也不是秘密凭据**；即使攻击者知道所有 `host_id`，仍不得跨账号或绕过配对。

| 实体 | 标识 | 说明 |
| --- | --- | --- |
| account | `account_id` | relay 登录与机器归属；密码仅存 Argon2id 哈希 |
| host | `host_id` + host 公钥 | relay 分配路由标识；host 自行生成身份密钥，私钥不离机 |
| device | `device_id` + device 公钥 | 控制端生成身份密钥；`device_token` 是独立的 relay 访问凭据 |
| 本机授权 | host 本地 grant | 绑定 host 身份、device 公钥、已确认能力范围、授权版本、有效期与撤销状态 |

**`device_token` 可绑定账号，但不能因此获得所有 host 的控制权。** 它用于账号内
的发现、配对协调与受限密文路由，不直接授权业务读写。host A 本机确认只建立
A 对该设备的信任；host B 及以后新增的 host 必须各自确认，不继承 A 的 grant。
这是设备信任范围，不是形态 2 的 observe / drive / approve 能力分层。

host enroll 使用一次性的账号登录会话完成归属登记，然后换成独立、可撤销的
host 连接凭据；不得为日常重连保存账号密码。后续注册须证明持有 host 身份私钥，
不能只凭 `host_id` 替换既有连接。重装、换密钥或归属改变后，旧 grant 失效并重新配对。

### 连接认证、路由授权与本机授权

- WebSocket 在握手或首个认证消息完成前，只接受认证流程，不发送业务数据。
  未认证连接须有超时与数量上限。认证后账号、设备和 host / 控制端角色不可切换。
- 每条消息仍由统一路由层检查目标 `host_id` 是否在连接的授权集合内。可以查
  内存中的授权对象，不要求每条消息查数据库，但不得跳过目标检查或分散到各处理器。
  消息来源绑定已认证连接；host 只能代表自身，客户端不能自报另一设备的发送身份。
- 连接授权不能永久冻结：过期、撤销、host 删除或归属变化须更新授权并关闭受影响
  的连接。身份不变，不代表权限永远不变。
- host 独立验证端到端对端身份与本机 grant。读取快照、订阅事件、发指令、审批均
  属于受保护操作；不能等到工具执行才检查。relay 宣称“账号已认证”不构成本机授权。

### 撤销语义

**relay token 撤销与 host 本地 grant 撤销是两个动作，不能互相冒充。**

- host 本机撤销立即使该 host 上该设备的连接与 grant 失效，清除尚未接受的输入，
  取消尚未执行且可取消的动作；执行入口再次检查撤销状态。已发生的副作用不能回滚。
- relay 接受 token 撤销后立即拒绝新认证与刷新，关闭所有关联连接，并清除该设备
  的未投递队列；不设宽限窗口。短寿命 token 不能代替这一处理。
- 多 host 撤销按 host 分别确认。离线或不可达的 host 显示“撤销待确认”，不得
  仅因 relay 返回成功就显示“所有机器已撤销”。跨 host 的本地 grant 撤销通知
  必须由目标 host 已信任且允许撤销的身份认证，不能由 relay 单独签发；具体
  恢复身份与投递方案尚待确定。恢复连接后先处理已收到的有效撤销，再接受操作。
- 恶意 relay 可以忽略 token 撤销或阻断撤销通知；此时只有已在目标 host 生效的
  本地撤销才是可靠执行边界。需要立即隔离时，在目标 host 本机撤销或关闭远控。
- 撤销一个设备不影响其他设备的 grant；账号注销、设备退出与 host 移除分别定义
  失效范围，不复用一个含糊的“断开”操作。

### relay 的数据模型

```text
account           id · 创建时间 · 密码 hash
device            id · account_id · 公钥 · 名称 · 注册时间
device_credential device_id · token hash · 过期/撤销时间 · 刷新凭据轮换状态
host              id · owner_account_id · 公钥 · 连接凭据 hash · 注册/撤销时间
```

一个 SQLite 文件存持久身份元数据，不存本机 grant、业务解密私钥或 transcript。
最后心跳等易失状态只保留在内存，除非有明确用途与有限保留期限。**这不是无状态
服务**：身份库、连接状态与投递缓存都属于状态，只是不持久保存业务内容。

数据库泄漏会暴露账号、设备和 host 的关系、公钥及凭据验证材料。密码哈希仍可能
被离线猜解；高熵 token 哈希不能直接当 token 使用，但不能据此声称“无凭据风险”。
数据库与备份均须限制访问并规定保留期限。

第一阶段使用 relay 本地账号与 Argon2id。模型 API key、MCP 密钥和本机 daemon
token 不进入 relay 的认证或存储流程。账号密码重置只能恢复 relay 账号，不能
新增、恢复或替换 host grant；管理员没有 host 授权入口。OAuth 可后续引入，
但也不替代设备配对、本机授权或安全的账号恢复流程。

访问 token 使用高熵随机值、短有效期；若支持刷新，刷新凭据必须有有限有效期、
轮换与重用检测，并绑定设备。认证材料不得放入 URL、日志或错误载荷；浏览器登录
会话优先采用 Secure / HttpOnly / SameSite cookie 并配合 CSRF 防护，不能将其
当作 host 授权凭证。具体寿命与刷新协议须在第一阶段协议冻结前确定。

## 配对流程

账号身份与本机设备信任分开建立。共八步：

1. 用户在可信控制端**先登录 account**；控制端生成设备身份密钥，私钥不上传。
   未配对阶段只有限时的发现与配对访问，不允许读取任何业务快照。
2. host enroll，登记 account 归属、host 身份公钥并取得独立连接凭据。
3. host UI 显示 QR：relay 地址 + `host_id` + host 公钥指纹 + 一次性 nonce
   + protocol version + 到期信息。**不含长期凭据**。配对 nonce 不写入访问日志，
   不跟随外部链接发送，不因扫码自动建立设备信任。
4. 手机扫码，核对 relay 地址并固定 host 身份；通过 relay 发起配对握手，提交
   device 公钥并证明持有对应私钥。不能把 relay 返回的公钥当作可信替代。
5. relay 校验 account 与 host owner，相异则拒绝；异常尝试只作限速后的通知，
   不用无限弹窗把 host 用户逼到误确认。此校验不是抵御恶意 relay 的唯一边界。
6. 两端用成熟配对协议验证握手，将 host 身份、device 公钥、目标账号与 host、
   nonce、有效期、relay 地址和版本绑定到同一次配对。host 与手机显示可比较的
   校验码，用户核对，防止 relay 替换设备密钥或串接另一份配对请求。
7. **host 本机要求确认这台设备对这台 host 的授权。** 展示设备指纹、校验码
   和上述“全部会话管理 + 只读工作区”范围，明确历史可见、回退可能修改文件。
   超时、信息不匹配或用户不在电脑前均拒绝。nonce 有短 TTL，并由 host 原子
   消费；relay 也做一次性消费与限速，但 host 不依赖它保证唯一性。
8. host 保存本机 grant，并向该设备发送经过认证的确认；控制端保存固定的 host
   身份。relay 签发或更新设备访问 token，但这个 token 不能替代 grant。

**一对一指一份完整配对记录、一枚设备公钥、一次本机确认与一个目标 host。**
配对失败、取消或过期后不留可复用的半授权；重新配对产生新的 nonce 与授权版本。

## 端到端安全边界

- 必须采用成熟、可审查的认证密钥交换和带完整性保护的加密协议，不自制密码协议。
  身份密钥、会话密钥和 relay token 分离；设备之间不共享账号级业务解密密钥。
- 已配对连接须双方证明持有固定身份密钥，不能只在第一次扫码时加密。会话密钥
  按连接派生，具备前向保密；分离方向与密钥周期，保证加密 nonce 不重复。
- 业务载荷以及它的 host、设备、会话/运行实例、消息类型、协议版本、序号和
  密钥周期须被完整性保护。relay 可见的路由字段与端内验证结果不一致时拒绝。
  外层路由标识尽量使用不暴露真实会话信息的短期 channel 标识。
- 消息防重放属于端到端协议，不依赖 relay 的 `seq_id` 或一次性消费承诺。
  重连后使用新密钥周期；不得把旧密文当成新操作执行。事件补发与命令重试采用
  下文不同的语义，端到端确认才证明对端接收，relay ack 仅证明中继收到。
- host 私钥与本机长期凭据存入系统凭据保护机制。PWA 如需持久保存设备密钥，
  使用不可导出的 Web Crypto 密钥并明确其局限：同源恶意脚本仍可调用密钥，
  浏览器配置文件被访问时也不能保证安全。禁止把长期 token 放入 localStorage。
- 第一阶段先确定协议、库、密钥生命周期与恢复办法，再写实现。身份验证或解密
  失败即关闭业务通道；没有明文回退、自动接受新指纹或降低版本的兼容路径。

**PWA 发布方仍在信任边界内。** 如果 relay 运营方也能修改控制端页面或 Service
Worker，它能下发恶意代码，读取解密后的内容或代替用户签发操作，端到端加密
不能解决这一点。PWA 应与 relay 运维凭据、发布流水线及来源隔离；即使隔离，
用户仍须信任控制端发布方。原生签名客户端可收紧更新边界，但也不是免信任方案。

## 消息面协议语义

不规定字段，只定必须有的语义：

- **双向，且 host 可反向发起请求。** host 主动推审批请求并暂停 turn 等手机回话，
  这是远程控制的核心交互，不是附加能力。
- **事件流带单调递增 `seq_id`。** 序号范围绑定 host、运行实例、流和方向，不能
  将不同流的同号消息当成同一条；识别缺口与重复后补发或重新拉快照。
- **分层 ack + 有界缓冲。** relay ack、对端已接收、host 已接受操作、执行结果
  分开表达。按消息数与总字节数限制队列，满了明确拒绝；慢消费者不能拖满全局缓存。
- **重连带游标**，端到端认证恢复后补发事件。快照携带同一流的基准游标，快照
  与增量之间不得漏事件。过期操作不能借事件重放恢复执行。
- **区分 relay generation、host 运行实例与密钥周期。** relay 重启或游标已过
  保留窗口时重新拉快照；host 重启使旧运行实例的审批失效；密码协议负责密钥周期。
  relay 声称 generation 变化不能单独授权重置命令去重记录或重新执行动作。
- **显式 protocol version**，握手不匹配直接断。
- **心跳双向。** 显示连接可达性与最近经端到端认证的 host 状态；超时显示
  “连接不可达/状态未知”，不能仅凭 relay 心跳断言 host 或 agent 已停止。
- **寻址显式带 `host_id`。** 同账号多 host 时不得省略，不得默认"最近活跃"。
- **操作使用独立 `operation_id`。** 同一设备对同一 host 的重试复用同一 ID，
  host 约束请求有效期并维护有界、跨重启的本地接受/结果记录。ID 绑定操作摘要、
  目标、授权版本及有效期，重试不能修改这些内容或延长 TTL；去重记录覆盖完整
  请求有效期，不能因队列满提前淘汰仍可重试的记录。接受记录先持久化，再执行
  副作用；存储失败则拒绝执行，记录无法恢复时结果标为未知，不当新操作接受。
  外部副作用无法通用保证“恰好一次”，未知结果先查询，不自动重试。
- **审批绑定具体动作。** host 生成唯一审批 ID，绑定 host 身份、device grant、
  会话与运行实例、动作及参数摘要、有效期和权限策略版本。控制端确认它看到的
  具体动作；host 执行前核对原请求并原子消费。参数、策略或运行实例变化即失效。
- **审批竞争有唯一终态。** 本机与多设备同时响应时，由 host 原子确定有效决定；
  迟到、重复、冲突或已取消的决定返回明确状态，不能再次执行或覆盖已消费审批。
- **未知消息默认不产生控制效果。** 可忽略明确标记为可选的展示事件；未知命令、
  审批字段和安全相关消息拒绝，不通过“兼容”绕过验证。
- **端点验证解密后的结构与大小。** 明确动作与字段白名单、字符串/集合/嵌套深度
  及截图解码尺寸上限；relay 限制密文帧与队列，不能替端点限制解压后或媒体解码后
  的内存。第一阶段默认关闭消息压缩，不把密钥与可控输入混合压缩。

### 断线输入与审批

普通指令可以进入有界、带 TTL 的 pending 队列，但恢复后必须先确认目标 host、
会话、授权和上下文仍有效。失效、撤销、超时或目标被删除时明确失败；状态变化
需要用户重新确认，不自动落到其他会话。第一阶段 pending 仅存内存，界面持续
说明尚未提交，关闭或重载会丢弃；主动离开时尽力提示，不依赖手机一定触发离开
回调，也不承诺跨重载可靠投递。

审批决定不作为可无限重放的普通输入排队。恢复后先向 host 获取仍有效的审批
状态；只允许提交对应请求的未过期决定。过期或运行实例变化后需 host 新建审批，
不能为了“全部可达”补执行旧决定。第一阶段只做逐动作审批，不做会话级打包授权。

## 分层职责

**Relay（服务器）—— 刻意做窄**

| 职责 | 说明 |
| --- | --- |
| 账号与设备凭据 | 注册、校验、过期、刷新与撤销；密码和随机 token 仅存验证哈希 |
| 连接注册表 | 固定连接身份与角色，按授权 `host_id` 和不透明 channel 路由密文 |
| 配对协调 | owner 校验、配对限速、nonce 消费、签发 token；不能创建 host grant |
| 投递层可靠性 | 有界密文队列、投递序号、补发、TTL、心跳；不决定动作执行结果 |
| 版本协商 | 显式 protocol version，不匹配即拒 |
| 浏览器来源校验 | 精确 Origin 白名单与 CSRF 防护，防跨站 WebSocket 劫持；不是设备身份认证 |
| 资源保护 | 每账号与全局连接/字节上限、帧大小、速率、认证超时和慢消费者处理 |

Relay **不持久存 transcript、不解密业务消息、不持有模型凭据或业务密钥、不做
agent 执行权限判定、不引入组织与能力分层**。它仍须做账号与路由授权，不能把
“不做业务权限”误写成“无需访问控制”。第一阶段只保留投递所需的有界内存密文
队列，不落盘；重启后端点重连，业务状态与命令接受记录由 host 保持。

> 不存 transcript 是数据最小化；端到端加密才使 relay 无法读取业务载荷。
> 新 client 的 catch-up 从 host 获取经过授权的加密快照，不能从 relay 身份库恢复。

**Host 守护进程（本机）—— 业务状态与执行授权源**

- 持有到 relay 的出站 WSS 长连，断线自动重连
- 本地通过认证的 loopback 接口访问 opencode serve；远控适配层只开放业务操作
  白名单，检查参数、会话范围与本机 grant。远端不能指定本地 API 路径、端口或 URL，
  适配层不提供模型/MCP 凭据读取、配置管理或远控安全策略修改接口。重连能力以
  真实底座行为为准，必要时由 host 保存有界事件窗口并生成一致快照，不假定
  底座所有事件都可重放。
- **BoundedOutboundBuffer**：已发出未确认的消息留在有界缓冲里，对端 ack 后
  才释放
- 心跳初始候选：ping 10s / pong 超时 60s；client idle 10 min；30s 扫一次。
  须在目标手机网络与负载下验证；心跳超时不替代 token 过期与撤销处理。
- **先验证设备身份、本机 grant 与动作，再调用既有业务路径。** 不接受远端
  自报 capability；工具审批继续走本机 permission，relay 传来的“已批准”不是
  许可。审批只解锁所绑定的本机待处理动作，不绕过 deny 规则或扩大原请求范围。
- 按已确认能力清单映射到本机业务路径，保存操作去重与审批终态，记录最小化审计；
  仅发送当前请求/订阅所需内容，不广播全部会话正文或文件。
- 把 relay 不可用当**优雅降级**而非故障：relay 挂了，本机 agent 照常跑，恢复后
  重连追平

**控制端（手机 PWA）**

- 无 opencode server 和模型配置凭据，但持有设备密钥并具有远程控制权
- 连上先向 host 拉**会话快照**，再订阅增量
- 会话操作经 relay 转给 host，先检查设备授权、范围与状态，再调用本机既有
  管理/执行路径。工具请求走原有 permission；会话管理与文件读取不能假装已被
  工具审批保护，也不能仅凭这一判断跳过远控授权。
- 掉线时普通指令有界排队并标记 pending；审批与失效输入按上文规则处理，不
  静默丢弃、不无限等待、不宣称尚未确认的操作已执行
- 审批展示完整关键参数、目标 host、会话、工作目录与风险；截断文字不能成为
  批准依据。具体内容来自经过认证的 host 请求，不信任 relay 拼出的审批描述
- 对仓库内容、模型输出、Markdown、终端控制序列和附件都按不可信数据渲染，
  不执行其中的 HTML/脚本/危险链接；外部图片默认不自动加载
- 使用严格 CSP、来源隔离与防嵌套页面策略；不加载第三方统计脚本。Service
  Worker 只缓存静态壳，不缓存业务响应；退出清理本地内容和密钥使用会话

## 威胁模型

显式区分网络攻击者、其他账号、relay 运营方、数据库窃取者和控制端发布方。
以下为设计目标，不代表尚未实现的系统已经通过验证。

### 防

| 威胁 | 手段 |
| --- | --- |
| 网络被动窃听 | 公网链路 TLS 1.2+，优先 1.3；业务额外端到端加密，无明文回退 |
| relay 读取、修改或伪造业务消息 | 固定端点身份、认证加密、完整性保护与端点防重放；不信任 relay 签发业务授权 |
| QR 被旁人拍到、配对密钥被替换 | 短期 nonce、双方握手验证与校验码、本机显式确认具体设备公钥 |
| nonce 重放 | host 原子消费与 TTL；relay 消费仅作额外防护 |
| 仅 device token 泄漏 | 短寿命、轮换与撤销；没有设备私钥和本机 grant 仍不能控制 host，但可能泄漏发现元数据 |
| 跨用户或跨 host 寻址 | 连接身份固定、统一逐消息路由校验、host 独立授权与显式目标 |
| 标识枚举 | 随机标识降低便利性，授权检查独立成立，拒绝响应不泄漏额外归属信息 |
| 浏览器跨站 WebSocket 劫持 | 精确 Origin 白名单、SameSite 与 CSRF 防护；非浏览器入口另行认证 |
| 重放命令或过期审批 | 操作 ID、内容绑定、TTL、运行实例、本机去重与审批原子终态 |
| relay 被拖库 | 不存业务明文/私钥；仍按账号关系、公钥与凭据哈希泄漏处置 |
| 输出触发控制端脚本或隐式外连 | 安全渲染、CSP、危险协议过滤、外部资源默认关闭 |
| 连接/消息资源耗尽 | 登录与配对限速、分层资源上限、背压和未认证连接超时；不承诺抗无限流量攻击 |

### 不防

诚实写明，避免过度承诺：

- **不防 host 本机已被控制。** 那时拿到的就是不折不扣的完全访问，relay 不设置
  第二道关卡（也做不到）。
- **不防控制端、浏览器环境或 PWA 发布链路已被控制。** 恶意页面、扩展、Service
  Worker 或设备访问者可能读取解密内容并使用设备密钥。HttpOnly 或不可导出密钥
  不能阻止所有代操作。端到端保密的前提是两端代码可信。
- **不防用户主动授权他人或交出完整设备身份。** 交出 token 与交出设备私钥的
  后果不同，但都不应描述成安全的共享方式；本方案不提供同事只读授权。
- **不防 relay 运营方看到元数据。** 包括来源 IP、账号—设备—host 关系、在线
  时间、流量大小和路由目标。可信端点下看不到业务载荷；不承诺隐藏流量模式。
  产品文档必须明示，自托管只改变信任对象，不消除云商或网络侧观察。
- **不防 relay 拒绝服务、选择性丢包或阻断跨 host 撤销通知。** 本机 agent 继续
  运行；界面不能把中继在线等同于 host 健康，也不能承诺离线 host 已即时撤销。
- **不防 prompt injection。** agent 读到恶意内容后产生的动作，仍由 host 侧
  permission 路径兜底，与本地执行时同等。

### Origin 与 TLS 的准确含义

Origin 白名单防浏览器跨站连接，不是 relay 地址白名单、设备认证或防中间人措施；
非浏览器客户端可以伪造 Origin。原生 host / CLI 没有 Origin 时，只能走独立、严格
认证的入口，不能允许未认证的缺失 Origin 请求绕过浏览器规则。

端点须验证预期 relay 域名、证书链并禁止 TLS 验证关闭。设备信任企业根证书时，
企业 TLS 代理仍可能通过证书校验；PWA 通常不能自行固定服务器证书。端到端加密
在可信客户端下保护业务载荷，但不能保护由代理替换的 PWA 代码。若要求拒绝这种
环境，需要另行设计受控客户端策略，不能仅靠“证书链校验”作保证。

## 隐私与数据最小化

代码库不搬上云不代表内容不经过网络：diff、终端输出、截图、会话快照可能包含
代码、模型密钥、个人文件或第三方数据。端到端加密限制中继可见性，不限制已授权
手机看到的内容，也不消除手机留存风险。

| 数据面 | 第一阶段要求 |
| --- | --- |
| 会话与输出 | 配对时本机明确授权该 host 全部会话与历史；允许列表与搜索，正文按需加载/订阅，不全量同步；发送前裁剪与脱敏 |
| 文件与 diff | 仅 host 本机已有项目中的只读内容与任务输出；检查路径、链接和解码大小；无直接文件写入、Git 写操作或终端输入接口 |
| 凭据与配置 | 不提供读取模型/MCP 密钥、daemon token 或配置备份的远控操作；输出意外包含密钥仍需处理 |
| 截图 | 仅明确请求时捕获已授权目标，不持续全桌面录制，不包含无关窗口；发送前提示敏感内容风险 |
| 手机存储 | 业务内容与 pending 默认仅存内存；不写 localStorage、IndexedDB 或 Cache API；持久设备密钥单独管理 |
| 浏览器缓存 | 敏感响应设置 `Cache-Control: no-store`，Service Worker 显式排除敏感响应；退出清理内容、队列与相关缓存 |
| relay 日志 | 不记录正文、token、nonce、完整 URL、认证头、真实会话 ID 或原始错误；身份关联最小化，IP 仅在必要安全用途下有限保留 |
| 本机审计 | 记录设备、目标、操作 ID、授权版本、时间和结果；不默认复制 prompt、diff、截图或完整命令参数 |
| 推送 | 默认仅“有待处理事项”；不带命令、文件路径、会话标题、diff 或可直接批准的链接，打开后重新认证 |

日志、账号关系、备份分别定义有限保留期限、访问权限与删除流程；删除账号须关闭
连接、撤销 relay 凭据并说明各 host 本地授权的处理状态。备份清理有延迟，应在
隐私说明中列明。保留期限、刷新凭据寿命和退出/忘记设备的密钥清理行为须在首个
外部试用前固定，不允许“默认永久”。

脱敏是补充措施，不是“任何输出都绝无密钥”的保证。用户在手机看到内容前，应
明确知道它会进入高权限控制端；若日后允许离线保存，须单独设计加密、解锁和擦除。
获准的 shell 或文件工具仍可能读取凭据文件或修改本机配置，这由本机工具权限与
执行隔离约束；远控操作白名单不是 agent 沙箱，不能承诺挡住所有工具间接访问。

## 先列出失败方式

按项目惯例，实现前先列失败方式。**协议、身份、审批、隐私和基础资源防护都属于
第一阶段要求**，不能因为早期界面只有一个账号就跳过。多 host / 多设备界面可以
后置，但隔离、撤销和竞争语义应提前在隔离环境用多个实体验证。

### A 组：连接与投递（协议必答）

1. relay 重启：host 重连后拿不到旧游标的响应；必须靠 generation 触发重新拉快照，
   不得继续用旧游标拼出一个空洞会话。
2. host 断线期间手机持续输入：普通指令有界排队并显示 pending；恢复后按目标、
   上下文和 TTL 验证，拒绝失效输入，不得乱序执行或静默丢弃。
3. 手机切 Wi-Fi / 4G 导致 IP 与连接变化：不得因此要求重新配对，device token
   必须与连接分离。
4. 消息乱序到达：序号必须能识别并重排，不得按到达顺序渲染。
5. ack 丢失导致重复发送：事件按流与序号去重；命令按操作 ID 与摘要去重，
   已执行但确认丢失时查询结果，不重新执行。
6. 出站缓冲打满：必须明确拒绝并让上层可见，不得无限增长也不得静默截断。
7. 快照与增量衔接有空洞：基准游标须与快照一致，缺口触发补发或重新同步。
8. relay ack 冒充端点确认：不能据此释放唯一恢复记录或显示操作已执行。

### B 组：身份与授权（形态 3 必答）

9. QR 被他人拍到：不得自动配对；确认须绑定具体设备公钥与校验码。
10. pairing nonce 重放：host 原子消费、过期拒绝，relay 重启也不能恢复旧配对。
11. device token 泄漏：没有设备私钥不得读取业务或控制 host；撤销须关闭旧连接、
    拒绝刷新并处理未执行队列，不仅在下一次登录时检查。
12. **A 账号不得寻址 B 的 host。** 建连时限制授权范围，统一消息路由仍检查目标；
    host 不信任 relay 自报的设备授权。
13. 攻击者已知所有标识：仍被授权检查拒绝，错误响应不泄漏其他账号归属。
14. 连接中途切换账号、设备或角色：必须拒绝，不把 host 连接当控制端使用。
15. 配对请求串扰或密钥替换：目标、身份、nonce 与版本绑定到同一握手，校验失败
    不创建 grant，不能仅展示 relay 传来的设备名称后确认。
16. 无人值守 host：超时拒绝；配对请求轰炸被限速，不自动批准。
17. relay 密码库泄漏：按哈希与账号关系泄漏处置，限制在线爆破；模型 key、端点
    私钥与 daemon token 不在库中。
18. 设备丢失或在线撤销：该 host 撤销后不接受该设备新动作；其他设备不受影响。
    多 host 不可达时显示撤销待确认，不承诺全局即时完成。
19. 同账号多 host：操作显式指定；host A 配对不授权 B 或未来新增 host。
20. 恶意 relay 签发假 token、篡改 owner 或注册假 host：不能绕过已固定的端点
    身份、本机 grant 与双方持钥证明；可以拒绝服务，但不能制造业务许可。
21. 账号密码重置、host 重装或换密钥：账号恢复不恢复 grant；host 身份变更须
    本机重新确认，不自动接受新指纹。
22. 远端输入任意本地 API/端口/配置操作：只开放业务白名单，未知动作拒绝。

### C 组：会话一致性与协议演进

23. 多设备同时看同一会话：每个已授权设备都得到对应加密事件，不得只推给最近一个。
24. 本机切会话：不隐式改变远端目标，事件须绑定原会话；远端显式切换时先结束旧
    订阅，不能把旧会话事件拼到新会话。
25. 会话删除或归档：按本机逻辑执行并明确显示状态；删除使相关 pending、审批
    与订阅失效，归档不隐式切换目标，也不借此绕过运行状态检查。
26. 断线、审批超时或 host 重启：恢复后重新获取有效审批；旧实例、过期、重复或
    参数已变化的审批不能执行。
27. 本机和多设备同时批准/拒绝：只有一个有效终态；已取消的危险动作不被迟到批准复活。
28. host / relay / client 版本混用：不匹配明确拒绝；未知控制语义不静默兼容。
29. host 执行后崩溃、结果未知：保留本地接受记录，查询或人工核实，不盲目重试副作用。

### D 组：隐私、资源与部署（基础防护不可后置）

30. 日志写满或泄漏正文：轮转、字节上限、脱敏与有限保留，含反向代理及错误日志。
31. 连接泄漏、巨帧、洪泛或慢消费者：分层连接/字节/速率上限与持续观测，单账号
    不能耗尽所有缓冲；未认证连接及时清理。
32. 企业 TLS 代理：证书不受信任时拒绝且不降级；根证书已被信任时不作必然拒绝
    承诺，按可信端点与 PWA 发布边界解释风险。
33. 非法 Origin、缺失 Origin 或恶意 relay 地址：分别验证浏览器来源、原生认证
    与预期地址/端点身份，不混用一种检查。
34. 恶意 Markdown、终端序列、附件或外部图片：不能执行脚本、加载隐私泄漏资源
    或伪造可信审批控件；密文被篡改不能进入渲染。
35. 浏览器缓存、退出或重载：敏感响应不进入 Service Worker 缓存，退出清理；
    pending 丢弃策略持续明示，不依赖离开回调，不假称已送达。
36. relay 抓包、内存观察与数据库/日志/备份检查：可信端点下只有业务密文，没有
    业务私钥；认证材料不出现在日志里。单次 grep 未命中不是保密证明。
37. PWA 发布或 Service Worker 被控制：属于端点失陷边界；须有发布隔离与撤销
    设备、更新/注销 worker、清缓存的恢复流程，不把它归为“端到端加密已防住”。
38. 推送或数据删除泄漏：通知无敏感正文，第三方通道披露元数据；账号删除、host
    授权清理和备份到期分别跟踪，不能以删一行数据库代替全部处理。

### E 组：已确认控制能力（第一阶段必答）

39. 全 host 授权被误认为只读：配对须明确全部历史、会话管理与 agent 执行能力，
    不借“只读工作区”隐藏实际控制权；不能因此获得另一台 host 的访问权。
40. 新会话夹带任意 cwd 或项目新增：只接受已有项目身份，内部运行参数由 host
    决定；文件读取拒绝路径穿越、越界链接与项目外目录。
41. 运行中发送语义漂移：普通发送按会话排队，不自动 steer 或中断；显式中断
    复用本机路径，排队状态、取消请求和执行结果分别可见。
42. 模型/agent 选择夹带权限或配置变更：只接受本机可用项，不传完整配置；未知
    选项、权限模式和 always 审批被拒绝，不修改 provider/MCP 或全局安全策略。
43. 永久删除或批量对象变化：明确对象清单与确认，先停止运行会话；部分失败逐项
    显示，不删除工作区文件，不把确认之后新增的会话算进原批次。
44. 本机与远端同时回退、删除或修改会话：host 检查会话与受影响工作树状态，
    冲突时拒绝并刷新；回退与继续在有效状态下仍复用本机行为。
45. 只读工作区变成全功能代理：文件编辑、Git 写操作、终端输入、设置与设备管理
    即使客户端伪造消息也被拒绝；通过会话请求 agent 操作仍按本机工具权限执行。

## 服务器选型

候选配置：香港可用区 B、Debian 12.7 64 位、2 核 2 G、峰值带宽 30 Mbps、
系统盘 60 G、月流量 600 GB、83.52 元/年。

**结论：可作为小规模试用的候选，不据此承诺容量。** 上述价格与系统版本是采购
快照，购买时重新核对；部署使用持续获得安全更新的版本。实际内存与流量取决于
连接数、每设备密文队列、截图大小和限速，须测量后确定人数与资源上限。

一个直观换算：30 Mbps ≈ 3.75 MB/s，600 GB 满速约 44 小时用完一个月额度。
文本会话通常较轻，但频繁截图、重放和异常请求可能显著增加流量，必须有告警与上限。

唯一必须额外花的钱：**一个域名**（几十块/年）。没有域名就没有可扫码的稳定
URL，也没有手机换网络时不变的入口。

已知限制，接受即可：活动机不支持换地域、中途删除按原价折算退款、限购一台
大概率不能原地升级。不能升级会限制可承载连接与缓冲容量；达到限额时先拒绝新增
负载并告警，扩容或多 relay 属于后续独立设计，不自动获得高可用。

> **形态 3 下的持续成本，买之前要知道**：这不是一次性 83 元。域名和服务器每年
> 要续；Debian 要定期打补丁；relay 一断，所有用户的手机同时失联（各自桌面端
> 仍在正常运行，只是遥控不到）。这些是运营负担，不是架构缺陷，但要对使用者
> 诚实。
>
> 如果将来还要在服务器上跑真实 agent 工作负载，2 G 内存和 60 G 盘会同时不够，
> 且 host 绝不该和 relay 部署在同一台公网机器上（见"不防"第一条）。那是另一个
> 采购决策，与本架构无关。

## 推进路线

**第一阶段：最小可用（形态 3 的单人切片）**

产品界面先做单账号、单 host、单设备、PWA、无推送。先确定成熟端到端方案与
配对协议、凭据寿命及资源上限初值，再实现 relay + host + 独立设备信任 + 事件恢复 +
操作去重 + 已确认的完整会话管理与控制 + 只读工作区。包含已有项目中新建会话、
会话选项、逐次审批/问题回复、排队/显式中断、历史分支/回退及分级删除/批量操作。
本机设备查看与撤销、在线连接失效、隐私缓存策略和基础部署防护同期交付，不能
等第二阶段才提供丢失设备处理；远端不提供设备授权管理入口。

覆盖 A—E 的基础安全与控制行为；隔离 E2E 必须含两个账号、两台 host 与两枚设备，
提前验证跨账号隔离、不隐式授权、撤销与审批竞争。多实体测试不意味着提前交付
完整管理界面。密码协议选型与安全验收未完成前，不开放真实工作区的外部试用。

**第二阶段**

多 host 寻址与切换、完整本机设备管理及逐 host 撤销进度。每台新增 host 独立配对，
不放宽第一阶段授权边界。另开推送通道；与控制通道分离不等于没有隐私风险，
第三方仅接收最小通知，并披露其可见元数据，不携带直接执行或审批凭据。

**第三阶段：谨慎**

形态 2 的能力分层（observe / drive / approve）。**到那一步之前，任何"给同事开
个只读权限"的需求都要顶住**——它要求 host 侧 permission 路径理解 capability，
是把权限模型从"本地同一把尺"改成"分层的尺"，远比听起来大。谁要这个，谁单独开
一篇文档。

组织、配额、计费、高可用多 relay 不在路线上。

## 与 Fintwind 现有组件的衔接

- **主机守护进程必须是独立进程，不进 GPUI 主线程。** 出站 socket 在后台跑，
  渲染只读内存中的快照。这是 [performance.md](performance.md) 的直接要求：
  从 `render` 可达的 I/O 是缺陷，一次阻塞调用就耗掉几帧预算。
- **复用 `fintwind-daemon` 的既有边界而不是另起一套。** 现有桌面启动使用
  loopback + `FINTWIND_DAEMON_TOKEN` 全控制能力凭据 + 单条 JSON 就绪记录；
  daemon 的可配置 bind 不等于已强制 loopback-only，远控部署必须核实并限制本机
  接入地址。host 守护进程作为对等组件，不塞进 GUI。本机全控制 token 不发给
  relay 或手机；远控适配层只映射已确认业务能力，不透明透传 daemon 命令。
- **复用本机会话路径，不复制一套业务逻辑。** 会话目录、持久 submission、
  permission/question 回复、分支/回退及文件/diff 读取可作为底座；现有结构不是
  远控授权证明。适配层补设备 grant、TTL、状态版本、唯一操作与结果查询，模型/
  agent 选择仅传允许项；本机全状态保存、工作区写操作和配置命令不作为远控入口。
- **relay 是新二进制，与 daemon 不是同一个东西。** daemon 是本机 loopback 服务，
  relay 是公网密文转发与身份服务。只有 host 的公网链路是出站；daemon 有本机
  监听，relay 有公网监听，不再用“都只出不进”描述两者。
- **长会话必须虚拟化。** 原生端沿用 `list()`；PWA 使用适合 Web 的虚拟列表。
  两端都按需获取有界内容，行构建器不得重建整个会话状态。
- **不要把 relay 协议绑死模型供应商。** 见上文"为什么是 Codex 路线"。

## E2E 验收产物

relay 与 host 各自可独立启动。在隔离数据目录、固定测试工作区及合成账号下，
逐一制造失败方式；不使用真实模型 key 或用户代码。每次保存可重复的启动配置、
版本与结果摘要，以及脱敏时间线（只记时间、阶段、测试别名、非敏感操作 ID、
端口、generation 与结果码；不记 token、nonce、私钥、prompt、附件、URL、
认证头和原始错误）。验收必须证明：

- 拍到 QR、重放 nonce、替换设备公钥或串接配对请求，都不能建立未经本机确认的 grant
- 未认证连接不收业务数据；A 账号建连或在已认证连接内寻址 B 的 host 均被拒绝
- host A 配对不授权同账号的 B 或新 host；错误、遗漏的目标不会默认落到其他机器
- 伪造 relay token、owner、设备授权或 host 公钥，不能绕过固定端点身份与本机 grant
- 仅 token 泄漏不能读取业务或控制 host；在线撤销关闭关联连接，旧 token/刷新失效
- host 本地撤销后旧设备与排队动作不能执行；不可达 host 明确显示撤销待确认
- relay 重启、游标过期及快照/增量竞争不拼出空洞会话，也不重置操作去重授权
- 断线输入按顺序接受或明确失败；过期、跨会话、被删除目标的输入不补执行
- 丢失 ack、重复命令与 host 崩溃不自动重复副作用；结果未知可以查询并明确展示
- 审批过期、host 重启、参数变化、重复或多设备冲突时，仅有效原请求产生一次终态
- 手机操作在 host 侧留下最小审计，与本地相同 permission 规则生效，不新增 bypass
- relay 观察点用已知合成载荷验证只见密文；篡改、重放和跨 channel 移植消息被端点拒绝
- 检查 relay 进程、反向代理、数据库、日志和备份边界无业务明文/私钥；日志无认证材料
- 恶意 Markdown/终端序列/外部资源不能执行脚本或伪造可信审批；退出后无业务缓存
- 洪泛、巨帧、慢消费者与未认证连接受上限约束，正常账号仍能在声明容量内使用
- 配对范围明确覆盖该 host 全部现有与后续会话；列表/搜索可用，正文按需获取而非全量同步
- 新会话只落在已有项目；自报 cwd、项目新增、路径穿越或越界链接均被拒绝
- 普通发送排队，显式中断、停止/继续、分支/回退与本机路径行为一致；冲突明确失败
- 删除与批量操作验证确认对象、先停再删、逐项结果，不删除文件也不扩大对象清单
- 已有模型/agent 可选但不能改变权限策略；远端 always、配置、设备授权和工作区写命令被拒绝
- 只读文件/diff/任务输出可用，交互式终端输入不可用；agent 仍能按本机权限完成获准工具动作

单次 grep 或 `cargo check` 不构成保密、授权或副作用去重证明。E2E 验证行为，
不能替代密码协议与实现审查。以上为未来实现的验收要求，不是本次文档修改已执行的测试。

## 未决问题

这些问题不得用默认行为绕过。前四项须在第一阶段实现前确定方案与初值，仅允许
隔离试验调优，外部试用前冻结；第五项在试用前发布，第六项属于后续产品路线：

1. **密码协议与库。** 明确认证密钥交换、配对校验码、前向保密、nonce/密钥周期、
   重连防重放和密钥恢复办法，并审查 Rust 与浏览器两端的可用实现；不自行拼协议。
2. **生命周期与资源数值。** 固定 token/刷新/grant 寿命、配对和操作 TTL、事件
   保留窗口、跨重启去重记录期限，以及每设备、账号和全局资源上限。
3. **账号恢复与跨 host 撤销。** 确定管理员重置、忘记设备、host 重装的流程；
   离线 host 的撤销确认必须可见，任何恢复流程都不自动重建 grant。
4. **本地适配与结果恢复。** 核实底座事件重放、审批 ID/有效期及执行结果查询
   能力，以及会话排队、批量对象确认和回退冲突检查的复用边界；缺少的安全语义
   由 host 适配层补足，不另造本机功能，也不将通用 API 全量暴露给远端。
5. **隐私说明与发布恢复。** 列明 relay/PWA/云商/推送服务各自可见信息、有限
   保留期限、备份删除延迟、PWA 信任边界及失陷后的设备/worker 清理流程。
6. **原生控制端是否值得提前。** 第一阶段保留 PWA，但不声称它能抵御页面发布方
   作恶。对更新链或受控设备有更高要求时，另评估原生签名客户端。

已确定而不再留作未决：relay 不持久保存业务消息；短时投递仅有界密文内存缓存；
手机第一阶段完整会话功能 + 只读工作区，全 host 会话明确授权，新增会话限已有
项目，不开放设置与设备授权管理；普通发送排队、显式中断，逐动作审批，分级删除、
先停再删，本机与远端并用且冲突拒绝。relay 不可达显示“连接不可达/host 状态
未知”和最后可信状态，说明本机可能仍在运行，不无限转圈、不误报 agent 停止。
