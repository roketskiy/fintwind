# 手机远控界面改造

## 已确认范围

用户要求“使用 Shadcn 组件构建完整的网页”。会话列表与对话为两个独立页面。最新反馈要求紧凑、清晰的信息层级，Composer 与桌面基本对等，可发图片和小文件；工具只需名称和运行状态，不传正文。桌面只改手机远控设置页与远控投影、命令，不改整个设置框架。不增加文件管理或终端。

移动端采用 React、TypeScript、Vite，以现有 shadcn/Base UI 提供交互原语，适配 BeautifulUI 的真实组件源码与设计基础。构建为静态文件，继续适配现有 Caddy 和加密 WebSocket。无 SSR，无新增网页后端，无第三方内容服务。

## 页面与状态

会话列表包括工作区选择、搜索、按日期分组的最近会话，以及新建会话。显示真实标题、更新时间和状态，不放演示数据。对话页显示 Markdown、可复制代码块、原文用户消息、审批、问答与固定输入区。返回列表保留滚动位置。草稿按会话隔离，只保存在内存。

对话按桌面消息与 transcript block 顺序投影，连续工具及思考用 shadcn Trace 分组。思考运行中展开，完成后折叠，用户可以手动调整。工具仅显示名称与完成、进行中、失败状态，不投影参数、输出或详情。新桌面通过 features 声明能力；旧桌面继续使用正文协议，网页不发送未知命令。问答逐题填写，检查页允许回看修改，最终一次提交；不自动推进或跳过必答。

按用户提供的 branch 截图，连续活动组由一个可展开标题收拢，子项使用细竖线与弯角分支连接。运行中默认展开、结束默认折叠，用户手动选择优先；思考正文仍可单独展开。保留消息边界、活动顺序、失败状态和原有滚动机制，不把工具正文加入分支。

代码块通过 Lowlight 常用语言语法在按需启动的共享 Web Worker 中高亮，日夜配色随当前主题切换。React 只渲染文本 token，不注入 HTML；复制始终使用原始代码。未知语言、超过 32,768 字符或 token 预算、加载失败时保留完整纯文本。流式变化短暂停顿后再着色，不为高亮发网络服务请求。

用户明确移除正文末尾的装饰性闪烁光标；运行状态只在“正在处理”旁使用已有点阵 loading，遵循减弱动态效果设置。用户也明确不为小样式改动额外发起代码审查，直接修改和页面核对。

用户明确要求消息结尾同时显示真实时间与本轮耗时。时间由桌面消息记录提供；一轮最后的助手正文使用真实完成时间，耗时使用该轮开始/完成时间之差，不重复标注中间正文。缺字段不造数据，不用浏览器当前时间代替历史消息时间。旧桌面可能只提供消息时间或完全不提供时间，网页按可用数据降级。

Composer 提供真实模型选择、Build/Plan、思考强度、已登记命令、停止、运行中追加排队、附件选择与粘贴图片。附件单个 2 MiB、最多 8 个、合计 8 MiB；通过 64 KiB base64 分片在现有加密通道传输。桌面后台导入 daemon 附件存储，发送只接受本次配对、同一会话生成的附件 ID，不接受手机传入本地路径。上传及修改不自动重试。未提交上传有数量、大小与十分钟期限，关闭配对释放内存；已导入未引用文件由 daemon 既有清理策略管理。

Composer 采用 PromptBar 的卡片与浮层结构。用户最新指令明确删除整个展开编辑功能，不把它藏进菜单；`+` 直接选择附件。不保留底部“命令”按钮。输入 `/` 显示会话真实命令与适用的 Goal 命令，支持上下键、Enter/Tab 选择及 Escape 关闭；选择只填写草稿，不自动发送。思考强度显示名称保持原样，不做翻译映射。

用户提供真实手机截图后，Composer 与提问不再把 InputGroup、胶囊 ToggleGroup 及默认 Card 间距叠在一起。`beautiful/prompt-bar.tsx` 从参考 PromptBar 的输入区、内凹控制表面和模型入口适配：模型与 `Build · 原思考强度` 同处输入卡工具栏，停止和发送使用 32px 可见表面，实际按钮 44px，不再额外占用一排模式栏。附件上传、命令补全和所有修改仍由原 Composer 逻辑处理。

`beautiful/approval-card.tsx` 与 `.css` 从参考 ApprovalCard 的“问题本身作为标题、纵向选项、小型指示器、紧凑页脚”结构适配。选项使用真实 RadioGroup／Checkbox，不使用胶囊 ToggleGroup；标题 14px、选项 13px、说明 12px，小型标记不意味着缩小整行点击范围。单题不显示无用上下箭头；自定义回答无重复标题；动作表面 32px、按钮命中区 44px。保留检查页和最终一次提交，不复制参考组件的自动推进、跳过或关闭行为。

按用户确认，Composer、提问／权限、Goal 和会话列表分组卡片统一使用顶部内发光、多层向下阴影和单层 1px 描边。共用 `--bui-card-surface` 与 `--bui-card-shadow`，日夜主题分别调整高光和阴影强度，不通过额外外圈阴影加粗描边，不改变布局尺寸、焦点样式或点击范围，不新增悬停、模糊滤镜或持续动画。

用户随后明确“优化会话选项的样式，所有的 UI 都做密集一点”，并追加“所有地方都紧凑一点，字体也小一点”。会话选项改为左侧标签、右侧内凹分段选择，外观设置复用相同分段表面；沿用现有 ToggleGroup 的选择与键盘行为，思考强度名称不变。会话行收紧至 56px，消息区间距 12px、手机侧边距 16px，提问卡内距 10px，Composer 空态目标高度 84px。正文 14px、会话标题及问题 13px、选项与思考 12px、辅助文字不低于 11px；可编辑文本仍为 16px，避免手机输入时自动放大。不改变根字号、不使用整体缩放，保留 44px 控件点击区、焦点样式和卡片质感。

用户进一步指出分段滑块周围的灰色轨道过宽。轨道与点击区分开绘制：单行可见轨道 36px、选中表面 32px、真实点击区 44px，轨道每侧只留约 2px；轨道背景不接收点击，不遮挡选项或焦点。

仅当桌面声明 `goals` 能力时显示 Goal 功能。目标卡显示真实目标、状态、轮次、工具次数与耗时，通过现有 `sendPrompt` 的 `/goal` 语法执行暂停、恢复和清除。轮次不是完成百分比，不绘制伪进度。

按用户后续反馈收紧整体密度：输入框空态为一行，Goal 默认显示可展开的目标摘要，会话行约 64px，提问卡内距 12px。减少空白而不是缩小正文；触屏点击目标保持至少 44px。1080p 是物理分辨率，布局按设备 CSS 逻辑像素与安全区域自适应，不按物理像素等比压缩。

打开对话直接读取 getSession，不再等待工作区和会话列表。Caddy 压缩静态响应，带 hash 的 assets 使用长期缓存，HTML 仍禁止缓存。未做网络速度实测，不声称实测加速。

明确处理未配对、初次连接、重连、离线、空列表、加载、会话不可用、操作失败和操作待确认状态。断线时不把修改操作自动重发。连接状态不等于桌面在线状态，不编造设备名称或型号。

手机布局适配安全区域和软键盘，保留浏览器缩放能力。触屏点击区域不小于 44 像素。设置支持日间、夜间与跟随系统，手动设置不会被系统配色覆盖。用户最新要求取消全部 hover：不再跟踪指针或绘制滑动高亮，原语中的 hover 变体统一仅在按下时生效，原始 hover 选择器同步改为 active。只保留点击反馈、必要的键盘焦点提示和真实状态，遵循减弱动态效果。弹层有标题，表单有标签，导航和操作可用键盘执行。

## 记住配对

同一浏览器重开网页可自动恢复。IndexedDB 只保存路由令牌与不可导出的 HKDF `CryptoKey`，不长期保存明文配对密钥。旧 sessionStorage 授权在首次恢复时迁移并移除。工作区、会话、页面选择与待确认操作标识可持久化，消息正文、草稿和附件不落盘。Web Locks 将同一配对限制为一个活动页面；浏览器缺少保护能力时拒绝连接。存储失败时不发送修改操作。

设置中的“忘记这台电脑”移除本浏览器授权与页面选择，并通知其他打开页面停止使用旧授权。电脑关闭、关闭远控、重新配对仍使旧授权失效；浏览器保留记录不改变桌面撤销边界。非导出密钥不等于防御同源脚本攻击，不加载第三方脚本。

## 参考与隔离预览

参考 https://github.com/slev12397/beautiful-ui ，固定版本 `44a274e598395ab61e7c96c26fda2758780253b7`。适配 SidebarNav、SearchList、GlideMenu、LoadingState、PromptBar、ThinkingState、ToolChips、StreamingText、TaskRows、ApprovalCard、CodeBlock 的适用结构与样式；保留 MIT 来源声明 `mobile/public/licenses/beautiful-ui.txt`。不带入演示数据、自动阶段计时器、Canvas 光效或不存在的业务组件。

视觉预览使用实际 `RemoteView`、Composer、对话和审批组件，单独入口 `mobile/visual.html` 与 `mobile/visual-frame.html`。使用 `bun run --cwd mobile build --config vite.visual.config.ts` 生成 `target/mobile-visual`，然后 `bun scripts/serve-mobile-visual.ts` 打印随机本地端口。静态服务仅监听回环地址，15 分钟自动结束，无子进程；CSP 禁止网络连接，预览不运行 `useRemote`，不连接真实会话、不发送真实消息。生产构建不包含预览入口或数据。

桌面页读取现有 RemoteUiStatus，不另建业务状态。保留正常页边距和约 560 像素内容宽度，标题右侧使用现有开关。配对卡突出状态与二维码，只保留复制配对链接、重新配对两个操作。关闭和重新配对继续使用原有撤销流程。

桌面手机远控入口移至固定导航栏的帮助入口上方，使用本地 Lucide smartphone 图标；设置分类列表不再重复显示入口。远控页不占用设置第二栏，键盘可以聚焦并用 Enter/Space 打开。

## 边界

沿用 `remote-control-protocol.md` 与 `remote-multiuser.md`。界面不能接触私钥或 daemon token。HTML 和远程图片不作为助手内容执行或加载。所有认证对用户隐藏。

用户已明确“改完后部署，我要看效果”。网页构建、静态审查后使用独立前端发布脚本部署，只重载 Caddy、不重启中继，保留旧版与回滚。用户最新要求：不得自行构建 release 或安装包，必须等用户当次明确指示。新增桌面投影能力需用户日后自行授权更新桌面，不能因网页需求自行打包。不启动 dev watcher。用户后续明确要求“在内置浏览器进行页面测试”，因此允许隔离预览的视觉与页面交互检查（校验、选项、检查页、弹层、键盘与响应式布局），但仍不向真实会话发送消息或答案，不运行真实远控接口和负载测试。允许 Muse 参与实现；静态审查继续使用 Muse，不使用 Luna。页面预览与构建结果均不代表真实远控功能验证。
