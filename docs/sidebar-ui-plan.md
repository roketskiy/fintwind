# 双层侧栏、统一顶栏与独立 Diff 审阅页方案

状态：实施中。第 1-6 步已实现；第 8 节新增的统一顶栏（顶栏步骤 1-4）已实现。
用量已从设置分类移出，成为第一栏的独立模式（WorkspaceMode::Usage）：第一栏
上部依次为会话、审阅、用量，底部为更新与设置（设置仍是最后一个元素）；设置
分类列表与命令面板不再提供用量入口，命令面板的"用量"命令直接进入用量模式。
用量页沿用原设置页内容与宽度，无第二栏，全宽渲染。
页面按用户要求命名为"审阅"（rail 入口与页面文案，en Review）。第二栏只做
导航与入口：项目/路径/分支行（分支菜单 + 刷新 + 拉取 + 推送）、目录菜单、
已暂存与未暂存分组（组头带全部暂存/全部取消暂存/全部丢弃文字动作）、底部
提交按钮；文件行不再放操作图标。单文件暂存/取消暂存/丢弃改为文字按钮，放在
Diff 阅读器的文件名旁（按该文件实际两侧状态显示）；提交改为对话框（提交到
当前分支：信息输入、AI 生成、仅暂存提交、暂存全部并提交两个动作）。丢弃
未跟踪文件保留独立确认弹窗。历史快照一律只读（写操作控件全部隐藏）。

工作分支：`feat/sidebar-ui`。

本轮追加统一顶栏方案，仅更新本文，不修改应用代码。已有阶段记录不代表新增顶栏已实现或通过验收。

## 1. 目标与已确认决定

- 采用用户提供截图中的双层侧栏：固定的最左窄图标栏，加随模式切换的第二栏。
- 不同时保留旧单栏和新双层侧栏两种布局。
- 第一栏提供三个同级入口：会话、源代码管理、设置。设置入口放底部。
- 将右侧面板的审阅迁移到独立的源代码管理页面，与会话界面同级。
- 源代码管理采用类似 VS Code 的组织方式，补齐日常 Git 操作。
- 会话列表继续按项目分组，不改成截图中的“最近会话＋项目列表”。
- Git 默认跟随当前会话的实际工作目录，包括会话的独立 worktree。
- 默认并排 Diff，可切换统一视图；暂存等操作先按文件实现，不做修改块或行级操作。
- **Git 历史仍留在会话右侧面板，不迁移。**
- 点击会话中的轮次 Diff 入口，跳转独立审阅页。
- 设置也接入第一栏，进入设置后不替换或隐藏第一栏。
- 增加贯穿整个窗口的独立顶栏，窗口控件上移，不再与内容标签竞争宽度。
- 顶栏与第一栏视觉一体；会话、源代码管理、设置共用顶栏，窗口按钮位置不随面板显示变化。
- 现有头部的侧栏开关、后退/前进、打开目录和右侧面板开关上移；标签自身的新增与关闭操作保留在标签行。
- 多标签继续沿用现有单行横向滚动，不新增“全部标签”菜单，不自动换行。
- 窗口控件采用 Ely `WindowControls` 的 Windows 分支作为具体实现参考，不新增 Ely Cargo 依赖，不使用 macOS 红黄绿控件。

## 2. 页面布局

| 模式 | 第二栏 | 主区域 | 右侧面板 |
| --- | --- | --- | --- |
| 会话 | 新会话、添加项目、搜索、项目分组及会话列表 | 对话、输入框、现有会话操作 | 保留现有功能，移除审阅 |
| 源代码管理 | 仓库/worktree 选择、提交信息、已暂存与未暂存文件 | Diff、来源选择、Git 工具栏 | 默认隐藏 |
| 设置 | 现有设置分类与搜索 | 对应设置页面 | 隐藏 |

### 统一顶栏与整体分层

窗口分成上下两层，而不是在现有标签行中继续压缩控件：

- 上层是固定的全窗口顶栏，跨越第一栏、第二栏、主区域及右侧面板。
- 下层为横向内容布局：第一栏、第二栏、主区域、可选右侧面板。
- 主区域与右侧面板的标签行位于顶栏下方，各占自己的内容宽度，保留现有标签高度。
- 会话、源代码管理、设置只切换下层内容，顶栏不随模式重新生成另一套窗口控件。
- 顶栏与第一栏使用连续的主题背景，形成 L 形外框。不以独立圆角卡片、间隙或粗分隔线将两者切开。
- 第一栏从顶栏下缘延伸到窗口底部；第二栏与各内容区域的纵向分隔线从顶栏下方开始，不贯穿顶栏。
- 顶栏留出真实的空白拖动区，不用会话标题、Git 工具或搜索框填满空白。
- 新顶栏会占用垂直空间；本次通过 Ely 的紧凑标题栏控制成本，不同时压薄标签行，也不再在第二栏顶部保留旧的窗口标题占位行。

顶栏操作分工：

| 位置 | 控件 | 行为 |
| --- | --- | --- |
| 左侧 | 第二栏开关、后退、前进、打开目录 | 从现有头部迁移，不保留重复入口；只折叠第二栏，不隐藏第一栏 |
| 中部 | 空白区域 | 拖动窗口；不放内容标签，不新增大型标题或搜索框 |
| 右侧 | 右侧面板开关、原有可选 FPS 指示、最小化、最大化/还原、关闭 | 窗口按钮固定贴右侧，右面板开关位于按钮前 |

- 会话标签和右侧标签不合并成全窗口标签；两组的新增标签及标签关闭按钮仍留在各自标签行。
- Git 操作、Diff 来源、设置搜索和模式内工具栏留在各自页面，不因“头部上移”迁到全窗口顶栏。
- 后退/前进沿用现有会话导航语义，不暗中改成跨模式历史；不可用时禁用，不为本次布局改造扩展新的导航栈。
- 打开目录针对当前模式的有效上下文：会话为当前会话实际目录，源代码管理为当前查看的工作目录；设置没有有效目录上下文时禁用。不因打开目录而切换会话或模式。
- 审阅和设置模式不允许右面板开关打破原定的隐藏规则；对应按钮禁用并说明原因，位置保留，避免窗口按钮或其他控件跳动。
- 多标签继续使用现有滚动、边缘提示、自动露出选中标签及键盘切换行为，不新增标签管理交互。
- 窄窗口优先保住布局开关和窗口按钮，打开目录及可选 FPS 指示可以隐藏，但功能应仍能从既有入口到达。不将窗口按钮挤入标签区，不缩小其命中范围。

### Ely 窗口控件的采用范围

参考源码：

- 仓库：`https://github.com/ZacharyZhang-NY/Ely-GPUI-Components`。
- 本轮查阅的本地 HEAD：`2f8b2f687cd1e9b98a7cd29d4e882d09406fc547`。
- `src/shell/chrome.rs`：`TitleBar`、`WindowControls`、`caption_buttons`。
- `src/theme/tokens.rs`：`titlebar_height`、`caption_button_width`、`caption_button_height`。

采用 Windows 控件的具体布局与交互状态，通过移植或适配接入本项目，而不是仅保留旧控件然后上移：

- 按钮从左到右为最小化、最大化/还原、关闭，位于窗口最右侧。
- 基准尺寸按 Ely：顶栏 38、单个按钮宽 46、按钮高为顶栏减 1，即 37；这些是基准逻辑尺寸，不是固定物理像素。Ely 原值使用 rem，在基准 rem 16 时对应上述尺寸。
- 顶栏与按钮共享尺寸来源，缩放时同步处理，避免按钮超出顶栏；不能只把旧的 48 高按钮容器塞入 38 高顶栏。
- 普通按钮使用轻量悬停背景，关闭使用危险色背景，最大化时切换还原图标。
- 用 Fintwind 的主题、图标、翻译与焦点机制实现，不接入 Ely 的主题、字体或 `init()`。
- 保留 `WindowControlArea::Min/Max/Close` 等原生命中区域以及 Windows 11 最大化悬停布局行为。
- 关闭沿用 Fintwind 的隐藏窗口行为，包括系统关闭请求；不直接照搬 Ely 默认的 `remove_window()`，不因此停止后台会话。
- 保留对窗口是否可最小化、可调整尺寸以及是否激活的判断；控件支持键盘操作、可见焦点和名称提示，不能照搬缺少这些能力的参考代码。
- 拖动和双击沿用本项目的 Windows 平台处理。空白区才属于拖动区，按钮、标签和其他交互区不得被拖动命中覆盖。
- 如复制 Ely 源码或资源，保留 MIT 许可与归属，并核对本项目固定 GPUI 版本的 API；本轮只写方案，不复制实现。

## 3. 源代码管理页面

### 3.1 工作目录与上下文

- 从第一栏进入时，默认选中当前会话的实际工作目录，而不是一律选择项目主目录。
- 明确显示项目名称、工作目录/worktree 和分支，防止在错误的目录执行 Git 操作。
- 提供手动切换工作目录的入口，不因查看其他目录而修改会话的工作目录。
  （已确认：切换入口从 Fintwind 已记录的目录中选择——跟随会话、各项目主目录、
  各会话 worktree；不提供系统文件选择器入口。）
- 返回会话时保持原选中会话。
- 所有写操作绑定点击时的工作目录；后台完成后不能将结果写入已经切换的目录视图。
- 切换会话、手动选择目录和历史快照之间的优先级见第 9 节的实现细化项。

### 3.2 文件列表

- 采用“已暂存的更改”和“更改”两个分组。
- 显示路径、文件状态和数量；支持查看新增、修改、删除、重命名、未跟踪及二进制文件。
- 同一文件同时有暂存与未暂存更改时，可以同时出现在两个分组。
- 点击已暂存文件查看暂存区 Diff；点击未暂存文件查看工作区 Diff。
- 提供单文件和全部文件的暂存、取消暂存动作。
- 丢弃动作的安全范围见第 4 节，不将两个分组的丢弃含义混用。
- 长文件列表使用虚拟化，不逐帧重建整个集合。

### 3.3 Diff 主区域

- 独立审阅页的主区域采用 GitHub PR 式单文件聚焦（已确认）：顶部文件导航
  （上一个/下一个、文件序号、来源标识、刷新），文件头显示路径、状态徽标、
  DiffStat（+N −M）与统一/并排切换；文件选择由第二栏分组列表与导航条承担，
  不再挂右侧文件树。右侧紧凑 Diff 与会话内活动 Diff 保持原样式，不随本次重构。
- 默认左右对照：左侧为修改前，右侧为修改后。
- 可切换为统一视图；保留行号、语法高亮、文本选择和上下文展开能力。
- 左右内容使用对齐的行/修改块，共享垂直滚动；不能仅把删除行和新增行机械拆成两个独立列表。
- 清楚标识当前文件和 Diff 来源，新增、删除、二进制等没有常规双侧文本的情况提供对应说明。
- 优先让点击文件后的阅读聚焦该文件；文件间切换保留合理的选择和滚动状态。
- 保留现有 Diff 来源能力：本轮更改、全部未提交、未暂存、已暂存、已提交、分支比较。
- 非 Git 目录、没有更改、加载中、查询失败、内容截断均有明确状态，不显示过期内容为新结果。

### 3.4 提交区域与工具栏

- 第二栏提供提交信息输入和提交操作。
- 默认只提交已暂存内容，不静默执行“暂存全部并提交”。
- 保留现有 AI 生成提交信息能力，以当前提交范围为输入。
- 提供分支选择/创建、刷新、Fetch、Pull、Push 等日常操作。
- 保留操作中的状态、成功反馈和可读错误信息，避免重复点击启动相同写操作。

## 4. Git 范围与安全默认值

本次范围：

- 查看工作区状态与 Diff。
- 单文件/全部文件暂存、取消暂存。
- 丢弃未暂存修改；对未跟踪文件删除单独说明并确认。
- 提交、AI 生成提交信息、推送。
- Fetch、Pull。
- 创建与切换分支。

不包含：修改块/行级暂存、强推、交互式变基、完整冲突解决器、stash 管理或完整 Git 客户端。

安全要求：

- 丢弃前展示目标目录、文件及操作影响，提供确认与取消。
- 丢弃未暂存修改不得修改暂存区。
- 删除未跟踪文件必须明确提示不可由普通 Git 恢复；不隐含删除整个目录。
- Pull 默认仅快进；分叉时提示，不自动合并、变基或 stash。
- 不默认强推，不绕过分支切换时 Git 对未提交修改的保护。
- 非 Git 目录仍可使用会话；源代码管理显示说明，不自动初始化仓库。
- 文件路径使用参数传递和字面路径语义，处理空格、Unicode、前导连字符和 pathspec 字符。
- 对新仓库无 HEAD、重命名、删除、未跟踪、二进制和冲突状态明确处理；高级冲突处理不在本次范围。

## 5. 会话轮次审阅

- “查看本轮更改”等入口切换到源代码管理页面，加载该会话该轮的历史 Diff。
- 清楚显示来源会话和轮次，并标记“历史快照 / 只读”。
- 禁用对该快照的暂存、取消暂存、丢弃和提交等写操作。
- 提供“返回会话”和“查看当前工作区”入口。
- 切回实时工作区后才恢复对应 Git 写操作。
- 历史快照缺失或加载失败时明确提示，不以实时工作区 Diff 冒充该轮 Diff。

## 6. 导航与状态保持

- 模式切换不关闭会话、不停止生成、不清空输入草稿。
- 返回会话恢复原滚动位置、选中会话、输入状态以及右侧面板。
- 审阅与设置隐藏右侧面板的呈现，不删除其标签或后台资源。
- 原生浏览器视图也必须隐藏，不能覆盖审阅或设置页面。
- Git 历史继续由现有右侧入口访问，不新建重复的独立历史页。
- 原有右侧审阅入口移除；旧快捷入口、会话链接和恢复状态统一转向独立审阅页，不能留下隐藏的右侧 Diff 标签。
- 各模式恢复焦点时，避免焦点仍落在不可见的输入框、终端或浏览器上。

工程原则：

- 用清晰的页面模式状态统一导航，不把审阅伪装成隐藏的右侧标签。
- Diff 阅读器可提取复用，但会话中的紧凑 Diff 不必随本次改造重做。
- Git、文件读取、网络请求与 Diff 解析放到后台，UI 只读内存快照。
- 目录、来源和刷新 generation 共同保护异步结果；写操作与查看快照分开管理。
- 复用现有 pane 缓存和虚拟列表，核对新增第一栏后的有效宽度、拖动边界和文本测量。

- Tab、Enter、Space 可以操作模式入口、文件动作、确认与取消。
- 长列表保持虚拟化，渲染不产生 I/O。
- 三种模式共用一条全窗口顶栏；第一栏与顶栏视觉连续，内容分隔线不切开顶栏。
- 第二栏及右侧面板显隐时，窗口按钮始终保持右上角位置，只存在一组，没有旧控件或空标题占位残留。
