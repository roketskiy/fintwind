# 思考档位

输入框现有的模型选项菜单读取 OpenCode V2 `/api/model` 返回的 `variants`。
模型发现先等待插件激活，并显式传入目录，避免冷启动空目录或共享服务默认目录
导致档位丢失。档位以 `model.variant` 传给会话；修改档位会让下一次请求重新
应用会话模型设置。模型切换失败不再被静默忽略。

## 供应商保存

添加供应商或保存模型列表时，会根据仓库根目录的
`models_thinking_modes.json` 自动补充模型档位和标记的默认参数。参考表编译进
程序，运行时不需要读取仓库文件。修改参考表后需要重新编译。

- 按模型 ID 或显示名称匹配，忽略大小写、空格和标点，支持供应商前缀。
- 不按模型家族模糊匹配不同版本；参考表未收录的模型保持原样。
- 保留已有同名档位、禁用标记和默认参数；只补充缺失值。
- 参考表个别模型标了多个默认档位，按原顺序取第一个；没有默认标记时不写入
  默认参数。重复的同名模型具有相同档位，名称规范化后共用一项。
- 沿用供应商编辑器现有的兼容配置格式（`provider`、`options`、对象型
  `variants`），由 OpenCode V2 规范化为 `settings` 和数组型 `variants`。
  本次不迁移整个配置文件，也不改动其他顶层设置。
- 已有供应商需要重新保存一次才能补写参考表档位。

## 推断范围与限制

参考表不是供应商请求协议定义。按“兼容接口尽量生成”的策略：

- OpenAI / Responses：使用 `reasoningEffort`，关闭对应 `none`。
- Anthropic：关闭或自适应使用对应 `thinking.type`，其余使用 token 预算；
  优先采用参考表预算，缺失时低/中/高使用 1024/8192/16384，极高、最高和
  扩展使用 24576。这是预设，不代表每个 Claude 版本都支持。
- Gemini：推断 `thinkingConfig` 的等级或预算。
- 其他兼容模型：等级使用 `reasoningEffort`，开关使用 `thinking` 或
  `enable_thinking`；纯开关不额外附加可能不被接受的 effort 值。

网关可能忽略这些选项，模型也可能拒绝某个值。配置被 OpenCode 接受、目录能
列出档位，不等同于真实供应商已验证。遇到不兼容时，应按该网关协议编辑模型的
档位配置；后续保存不会覆盖已有同名档位。UI 只展示服务器实际返回的档位，
不会把未写入配置的参考表条目当成可用选项。
