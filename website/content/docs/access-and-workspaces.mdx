## Build or Plan

- **Build** lets the agent make changes and run the actions allowed by the selected access level.
- **Plan** is for inspection and a proposed approach without making changes.

## Access levels

| Mode | Best for |
| --- | --- |
| **Supervised** | Review every command and file change before it runs. |
| **Auto-accept edits** | Let file edits proceed, but ask before other actions. |
| **Auto** | Let an AI reviewer approve routine actions; risky actions still ask. |
| **Full access** | Allow commands and edits without confirmation in a workspace you trust. |

An agent may support only some of these choices. Waku shows the modes that can actually be honored.

When a permission prompt appears, choose **Allow once**, **Allow for session**, or **Always allow** according to how broadly you want that decision remembered.

## Local checkout or new worktree

Choose **Local** when the task should operate in the project's current checkout. The agent, terminal, file browser, and Review panel all see that same working tree.

Choose **New worktree** when you want an isolated branch for parallel or experimental work. Pick its base branch before the first message; Waku prepares the worktree when the task starts.

Use the branch picker to switch the local checkout, or to select the base branch for a new worktree. Branch and workspace controls are unavailable while a turn is running.

<Callout type="warn" title="Full access is intentionally broad">
  Use it only when you trust the project, its instructions, and the selected agent. For unfamiliar repositories, start with Supervised or Plan.
</Callout>
